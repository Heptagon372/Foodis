# Foodis 서버 배포 가이드 (VPS + GitHub Actions)

> 대상: Ubuntu 22.04 / 24.04 VPS, 도메인 `foodis.cloud`, GitHub `Heptagon372/Foodis`
> 결과: `git push origin main` → 서버 자동 빌드·재시작, HTTPS 적용된 `https://foodis.cloud`

---

## 전체 그림

```
[로컬 PC] ──git push──▶ [GitHub]
                           │ Actions
                           ▼
                     [SSH] ──▶ [VPS: Nginx :443] ──▶ [PM2: Next.js :3000] ──▶ [Supabase]
```

---

## 사전 준비 체크

- [ ] VPS SSH 접속 가능 (`ssh root@<서버IP>`)
- [ ] 도메인 `foodis.cloud` 소유, DNS 관리 가능
- [ ] GitHub 레포 `Heptagon372/Foodis` 접근 가능
- [ ] 로컬 `apps/web/.env.local` 에 Supabase/AI 키 들어 있음

---

## 1단계. 서버 초기 세팅 (한 번)

로컬에서 SSH 접속:
```bash
ssh root@<서버IP>
```

서버 안에서 세팅 스크립트 실행 (레포 raw 링크로 바로):
```bash
curl -fsSL https://raw.githubusercontent.com/Heptagon372/Foodis/main/scripts/deploy/server-setup.sh -o setup.sh
chmod +x setup.sh
sudo ./setup.sh
```

이 스크립트가 하는 일:
- `deploy` 유저 생성 + sudo 권한, root SSH 키 복사
- Node 20, pnpm 10, PM2, Nginx, Certbot 설치
- UFW 방화벽 (SSH + Nginx만 허용)
- `/var/www/foodis` 에 레포 clone
- 자동 보안 업데이트 활성화

끝나면 **로그아웃**한 뒤 다시 `deploy` 로 접속되는지 확인:
```bash
exit
ssh deploy@<서버IP>
```

## 2단계. 도메인 DNS A레코드

도메인 등록처(가비아, 카페24, Cloudflare 등) 대시보드:

| 레코드 | 호스트 | 값 |
|---|---|---|
| A | `@` | `<서버 공인 IP>` |
| A | `www` | `<서버 공인 IP>` |

전파 확인:
```bash
dig +short foodis.cloud
dig +short www.foodis.cloud
```
공인 IP가 뜨면 OK (최대 수분~수십분 걸림).

---

## 3단계. 환경변수 업로드

로컬 PC에서 (현재 디렉터리에서):
```bash
scp apps/web/.env.local deploy@foodis.cloud:/var/www/foodis/apps/web/.env.local
```

> ⚠️ `.env.local` 은 **절대 git에 커밋 안 함** — 서버에만 직접 올린다.
> AI 키·Supabase service_role 키가 들어 있으므로.

Google TTS 서비스 계정 JSON 쓰고 있다면 그 파일도:
```bash
scp apps/web/google-tts-key.json deploy@foodis.cloud:/var/www/foodis/apps/web/
# .env.local 안의 GOOGLE_APPLICATION_CREDENTIALS 경로를 서버 절대경로로 맞춰줄 것:
#   /var/www/foodis/apps/web/google-tts-key.json
```

## 4단계. Nginx + SSL 설정

서버에서 (`deploy` 로):
```bash
cd /var/www/foodis

# Nginx 설정 적용
sudo cp scripts/deploy/nginx-foodis.cloud.conf /etc/nginx/sites-available/foodis
sudo ln -sf /etc/nginx/sites-available/foodis /etc/nginx/sites-enabled/foodis
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# Let's Encrypt 무료 SSL (대화형 — 이메일 입력 + Yes 몇 번)
sudo certbot --nginx -d foodis.cloud -d www.foodis.cloud
# 끝날 때 "Redirect HTTP to HTTPS?" → 2번(Redirect) 선택

# 자동 갱신 테스트 (실제 갱신은 안 하고 drill)
sudo certbot renew --dry-run
```

이제 Nginx는 포트 443으로 들어온 요청을 `127.0.0.1:3000` 으로 넘긴다.

## 5단계. 첫 빌드 & PM2 start

서버에서 (`deploy` 로):
```bash
cd /var/www/foodis

# 의존성 설치
pnpm install --frozen-lockfile

# Next 프로덕션 빌드
pnpm --filter web build

# PM2로 띄우기
sudo mkdir -p /var/log/foodis && sudo chown deploy:deploy /var/log/foodis
pm2 start scripts/deploy/pm2.config.cjs
pm2 save

# 재부팅 시 자동 시작
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u deploy --hp /home/deploy

# 상태 확인
pm2 status
pm2 logs foodis --lines 50
```

브라우저로 `https://foodis.cloud` 열어서 뜨는지 확인.

## 6단계. GitHub Actions 자동 배포

### 6-1. 배포 전용 SSH 키 만들기 (로컬 PC)

```bash
ssh-keygen -t ed25519 -C "foodis-deploy" -f ~/.ssh/foodis_deploy -N ""
# 생성됨:
#   ~/.ssh/foodis_deploy       (개인키 — GitHub Secret에 넣을 것)
#   ~/.ssh/foodis_deploy.pub   (공개키 — 서버에 넣을 것)
```

### 6-2. 서버에 공개키 등록

```bash
# 로컬에서 서버로 공개키 전송
ssh-copy-id -i ~/.ssh/foodis_deploy.pub deploy@foodis.cloud

# 또는 수동으로:
cat ~/.ssh/foodis_deploy.pub | ssh deploy@foodis.cloud "cat >> ~/.ssh/authorized_keys"
```

접속 되는지 확인:
```bash
ssh -i ~/.ssh/foodis_deploy deploy@foodis.cloud "echo ok"
```

### 6-3. GitHub Secrets 등록

GitHub 레포 → **Settings → Secrets and variables → Actions → New repository secret**:

| 이름 | 값 |
|---|---|
| `SSH_HOST` | `foodis.cloud` 또는 서버 IP |
| `SSH_USER` | `deploy` |
| `SSH_PORT` | `22` (기본 포트면 생략해도 됨) |
| `SSH_PRIVATE_KEY` | `~/.ssh/foodis_deploy` **파일 내용 전체** (`-----BEGIN` 부터 `-----END OPENSSH PRIVATE KEY-----` 까지) |

### 6-4. 테스트

```bash
# 로컬에서 아무 커밋이나 main에 push
git commit --allow-empty -m "chore: 자동 배포 테스트"
git push origin main
```

GitHub → **Actions** 탭 → **Deploy to VPS** 가 초록불로 끝나는지 확인.
혹은 수동 실행: Actions 탭 → Deploy to VPS → **Run workflow** 버튼.

## 7단계. 보안 마감 (선택이지만 강력 추천)

### 7-1. SSH 비밀번호 로그인 비활성

```bash
sudo nano /etc/ssh/sshd_config
```

다음 값들을 바꿔둔다:
```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```
```bash
sudo systemctl reload sshd
```
> ⚠️ **반드시 새 터미널에서 `ssh deploy@foodis.cloud` 가 성공하는 걸 확인한 뒤에** 기존 세션 닫을 것. 안 그러면 자물쇠 밖에 두고 열쇠 안에 두는 꼴.

### 7-2. fail2ban (SSH 무차별 대입 차단)

```bash
sudo apt-get install -y fail2ban
sudo systemctl enable --now fail2ban
```

## 트러블슈팅

| 증상 | 원인·해결 |
|---|---|
| `502 Bad Gateway` | Next가 안 떠 있음 → `pm2 status`, `pm2 logs foodis` |
| Certbot 실패 "no A record" | DNS 전파 전 → `dig +short foodis.cloud` 로 IP 확인 후 재시도 |
| `pnpm: command not found` (CI) | 서버에 pnpm 미설치 → `npm i -g pnpm@10` |
| 빌드 중 OOM | 1GB VPS 흔한 문제 → swap 2GB 추가: `sudo fallocate -l 2G /swap && sudo chmod 600 /swap && sudo mkswap /swap && sudo swapon /swap` 후 `/etc/fstab`에 `/swap none swap sw 0 0` 추가 |
| Supabase RLS 실패 | `.env.local` 의 `SUPABASE_SERVICE_ROLE_KEY` 가 서버에 없음 → scp로 다시 올림 |
| GitHub Actions "Permission denied (publickey)" | `SSH_PRIVATE_KEY` 가 BEGIN/END 줄 포함 전체인지, 서버 authorized_keys 에 그 공개키 들어있는지 확인 |
