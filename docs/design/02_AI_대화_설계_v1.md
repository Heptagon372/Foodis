# 🎙️ AI 대화 설계 v1 — 의도·슬롯·답변 규칙·할루시네이션 테스트 셋

> 03 문서(시나리오·데모 10문항·답변 UX 규칙)와 04 문서(RAG ①~⑧·5감의 방어)를 **코드로 동작하는 규칙**으로 확정한 기록.
> 로드맵 P1 "데모용 음성 질문 10개 + 기대 답변", P3 "AI 답변 스키마·시스템 프롬프트 v1", "할루시네이션 테스트 셋 30문항"에 해당.

## 1. 의도 분류 — 규칙 우선, LLM 은 애매할 때만

규칙이 판단하면 LLM(Haiku) 호출을 건너뛴다 → 지연 0.4초 예산 + 비용 절감. 데모 10문항은 **전부 규칙만으로** 분류된다.

| 순서 | 규칙 (발화에 있으면) | 의도 | 대상 음식 필요 |
|---|---|---|---|
| 0 | 특정 음식 + 식이 단어 + "먹어도/돼?/괜찮" | explain_food (식이 질문) | ✓ |
| 1 | 몇 개/나라/국가 · 패스포트 · 탐험했 | passport_status | |
| 2 | 비슷한 · 닮은 · 같은 재료 · 다른 나라에도 | compare_similar | ✓ |
| 3 | 기원 · 유래 · 역사 · 뭐야 · 어느 나라 · 어떤 음식 | explain_food | ✓ |
| 4 | 문화 · 이야기 · 어떻게 먹 | culture_story | |
| 5 | 추천 · 어디로 · 뭐 먹 · 떠나 (또는 "알려줘/보여줘" + 음식 이야기) | recommend / 식이 단어 있으면 filter_by_diet. 음식 이름을 콕 집으면 explain_food | |
| — | 위에 없음 | LLM 분류. LLM 장애 시 음식 이야기면 recommend, 아니면 out_of_scope | |

"대상 음식" = **질문에서 이름으로 가리킨 음식 → 없으면 화면에 떠 있는 음식** 순. 이름이 우선이라 터키 커피 화면에서 "비엔나 커피 이야기도 들려줘"가 제대로 이어진다.

## 2. 슬롯 — 항상 DB 와 대조

| 슬롯 | 추출 | 비고 |
|---|---|---|
| 국가 | countries.name_ko/en, **긴 이름 우선**(인도네시아 > 인도) + 별칭(터키→튀르키예, 한국→대한민국, 남아공) | 음식 이름 안의 국가명(튀르키예 커피)은 국가로 보지 않음 |
| 대륙 | 아시아 · 유럽 · 중동/아프리카 · 아메리카/남미 | Passport 후속 질문 "유럽 음식 추천해줘" |
| 음식 | foods.name_ko/en 최장 일치 + 표기 별칭(세비처→세비체, 살테나스→살테냐, 교자→자오쯔) | 음성 인식 표기 차이 흡수 |
| 식이 | 비건 · 채식 · 할랄 · 글루텐 · 유제품 | 프로필 식이와 **합집합**으로 필터 |
| 지도에 없음 | "○○ 음식/요리", "○○은 어떤 음식이야?"의 ○○가 국가·대륙·DB 음식이 아님 / LLM 의 mentioned_food·mentioned_place 가 DB 에 없음 | → "제 음식 지도에는 아직 없네요" + DB 안의 대안 1개 (04 §5-3) |

**LLM 이 뽑은 이름도 DB 와 대조해서만 쓴다.** "부리토"를 LLM 이 음식으로 인식해도 DB 에 없으면 설명하지 않고 '지도에 없음'으로 간다.

## 3. 의도별 검색과 카드 수 (03 문서 §4: 카드 1~3)

| 의도 | 후보 | 카드 | 식이 필터 |
|---|---|---|---|
| recommend | 하이브리드 검색(국가·대륙 슬롯, 미탐험 가산, 이번 대화에서 본 음식 제외) | 1 | ✓ |
| filter_by_diet | 같음 | 최대 3 | ✓ |
| compare_similar | 검수된 관계 → 없으면 벡터 유사 | 최대 3 (대상 음식 제외) | ✓ — **전부 걸리면 엉뚱한 음식 대신 "조건에 맞지 않아요"** |
| explain_food | 대상 음식 1개 | 1 | ✗ ("먹어도 돼?"에는 DB 값대로 정직하게) |
| culture_story | 대상 음식, 없으면 culture_story 있는 음식 | 1 + 역사적 연결로 "이어 듣기" 추천 질문 | ✗ |
| passport_status | — | Passport 요약 카드 + 덜 간 대륙 추천 질문 | — |

## 4. 답변 규칙 (프롬프트 `lib/foodi/prompts/answer.v1.ts`)

- 사실은 후보 데이터에서만. 식이는 yes 만 "가능", depends 는 "조리법에 따라 달라 확인 필요", unknown 은 "아직 확인 안 됨".
- 15초(2~3문장), culture_story 만 60초. 해요체, 괄호·이모지·목록 없이. 출처는 화면에만.
- 사용자가 원하지 않는 음식을 먼저 꺼내 "이건 안 돼요"라고 하지 않는다 (시나리오 B).
- 서버 검증(`validate`)이 막는 것: 후보 밖 food_id · 후보 밖 음식명 · 추천 계열의 식이 조건 위반 · **DB 가 no/unknown 인데 "비건이에요"처럼 단정하는 문장**. 실패 → 1회 재생성 → DB 템플릿.
- LLM 없이 나가는 **템플릿 답도 의도별로 설계**: 조사(은/는·을/를·와/과·으로/로) 자동, 나라 이름 중복 제거, depends 면 diet_note 로 이유까지.

### 설계 중 고친 기획 간 불일치
- **데이터 문체**: `s05` 는 summary 를 "해요체 금지, 평서문"으로 쓰게 했지만, DB 스키마는 summary 를 "음성용"으로 정의했고 푸디는 해요체로 말한다(03 §5) → 실데이터로 템플릿·"듣기"를 쓰면 한 답 안에서 말투가 바뀐다. **s05 를 해요체·괄호 없음으로 수정.**
- **"만두"는 음식 이름이자 일반 명사** ("폴란드 만두예요"). 검증기가 이를 '후보 밖 음식'으로 오인 → 후보의 DB 문장·사용자 질문에 이미 있는 말은 허용하도록 수정.

## 5. 데모 필수 10문항 — 현재 동작 (미리보기 데이터, LLM 없이)

| # | 질문 | 의도 | 결과 |
|---|---|---|---|
| 1 | 오늘은 어디로 떠나볼까? | recommend | 카드 1 + 추천 질문 3 |
| 2 | 내가 아직 안 가본 나라 음식 알려줘 | recommend | "페루는 아직 안 가보셨네요. 세비체, 어때요?" |
| 3 | 채식주의자인데 인도 음식 추천해줘 | filter_by_diet | 인도 채식 음식 3 (버터 치킨 제외) |
| 4 | 이 음식 어느 나라 음식이야? (팔라펠) | explain_food | 대표 국가 + "기원과 범위에 대해서는 여러 이야기가 있어요" |
| 5 | 음식 문화 이야기 하나 들려줘 | culture_story | 튀르키예 커피 이야기 + [비엔나 커피하우스 커피 이야기도 들려줘] |
| 6 | 비슷한 음식 있어? (만두) | compare_similar | 자오쯔 · 모모 · 만티 |
| 7 | 나 몇 국가 탐험했어? | passport_status | 요약 카드 + "다음엔 유럽으로 가볼까요?" |
| 8 | 할랄 음식만 보여줘 | filter_by_diet | 3장, 조리법 따라 다른 것은 노란 배지 + 안내 |
| 9 | 김치의 기원 알려줘 | explain_food | DB history 그대로 + "정확한 시점은 자료마다 조금 달라요" |
| 10 | 화성 음식 추천해줘 | out_of_scope | "화성은 제 음식 지도에는 아직 없네요. 대신 …" + 카드 1 |

## 8. 사진 인식 (F-VIS-01)

> 07 PRD "사진 → Vision LLM 이 후보 3개 제시 → DB 매칭된 것만 카드로", 09 문서 "Claude Vision 에 사진 + FOODIS DB 음식 이름 목록을 함께 주고 후보 3개만 고르게 한다". 대화와 같은 원칙 — **DB가 사실, AI는 고르기만**.

**흐름** (`components/PhotoAsk.tsx` → `POST /api/foodi/vision` → `lib/foodi/vision.ts`)
1. 푸디 시트 입력창 옆 📷 → `<input type="file" accept="image/*" capture="environment">` (모바일은 후면 카메라 바로).
2. 브라우저에서 캔버스로 **긴 변 1024px 이하 JPEG**(품질 0.85 → 넘치면 0.7·0.55)로 줄여 base64 JSON 으로 보낸다. 피드에 썸네일 턴 "📷 사진으로 물어봤어요".
3. 서버 검증: content-length 상한 → `checkImagePayload`(JPEG·PNG·WebP 만, base64 형식, **1.5MB 이하**, 선언한 형식과 파일 앞 바이트(매직 넘버) 일치) → 속도 제한 **분당 5회 · 하루 30회**(사용자·IP별, 대화의 분당 10회와 별도) → 일일 예산(`DAILY_BUDGET_USD`, 대화와 같은 `api_usage` 합계).
4. 후보 목록 = 검수된 음식 전체(`allFoodNames` + 나라 이름). UUID 대신 **짧은 키 `F1…`** 로 넘긴다 (230여 개 × UUID 는 수천 토큰) — 시스템 프롬프트에 `키 | 한국어 | 영어 | 나라` 표로 넣고, id 순으로 고정해 목록이 그대로면 프롬프트가 매번 같다.
5. Vision 호출: `LLMProvider.structured({ image })` → Anthropic `messages.parse` + `zodOutputFormat`, 이미지 블록을 텍스트 앞에. 모델은 `LLM_MODEL_VISION`, 비우면 `LLM_MODEL_FAST`(Haiku 4.5), `max_tokens` 400, 이미지 요청만 타임아웃 12초.
   출력: `{ is_food, candidates: [{ food_id, confidence: high|medium|low, reason_ko }] }`.
6. **서버 방어선** `pickCandidates`: `is_food=false` → 0개 · 목록 밖 키/지어낸 이름 버림 · 같은 음식 중복 제거 · 최대 3개 · 이유 60자 자름. 그다음 `getFoods`(verified 만) → 대화와 같은 `toCard` 로 카드 (식이 배지·요약·이미지는 DB 값). 모델이 쓴 말은 "사진과 닮은 이유: …" 한 줄과 닮은 정도 칩뿐.
7. 0개면 "제 지도에 있는 음식 중에는 닮은 게 없어요" + 이어지는 질문 칩. 카드가 있으면 첫 음식 이름으로 "○○ 이야기 들려줘 / ○○과 비슷한 음식 있어?" 칩 → 일반 대화로 이어진다(첫 카드가 맥락 음식).

개수(≤3)·길이(≤60자)를 zod 스키마에 강제하지 않은 이유: 한 글자 넘쳤다고 호출 전체가 파싱 실패하지 않게 하고, 서버에서 자른다.

**실패 처리**
| 상황 | 응답 | 화면 |
|---|---|---|
| `ANTHROPIC_API_KEY` 없음 (미리보기 모드) | 503 `vision_unavailable` | "사진 인식은 준비 중이에요 (AI 키 설정 후 열려요)" |
| 일일 예산 초과 | 503 `vision_budget` | 글·음성으로 물어보라는 안내 |
| 모델 오류·타임아웃 | 503 `vision_failed` | 다시 찍거나 글로 물어보기 |
| 형식·크기 위반 | 415 / 413 / 400 | 서버 메시지 그대로 |
| 속도 제한 | 429 | "잠시 후" / "오늘은 여기까지" |

**비용 추정** (추정치 — 키 발급 후 `api_usage` 로 실측)
- Claude 이미지 토큰 ≈ 가로×세로 / 750. 1024×1024 ≈ **1.4k 토큰**, 1024×768 ≈ 1.05k.
- 후보 목록: 음식 1개당 약 12~15 토큰 → 230개 ≈ 3~3.5k 토큰 + 규칙 ≈ 0.4k.
- Haiku 4.5 ($1 / $5 per 1M): 입력 ≈ 5k × $1 + 출력 ≈ 150 × $5 → **1회 약 $0.006**. 일일 예산 $5 이면 대화와 합쳐서 계산되므로 사진만 쓴다면 하루 약 800회.
- 목록이 고정이라 나중에 프롬프트 캐시를 붙이면 목록 부분은 캐시 읽기 가격으로 줄일 수 있다 (Haiku 4.5 최소 캐시 길이를 넘는지 실측 후 결정).

**개인정보**
- 사진은 요청 메모리에서만 쓰고 **저장하지 않는다**: DB·스토리지·대화 로그(`conversations`)에 남기지 않고, 에러 로그에도 본문 없이 메시지만. `api_usage` 에는 토큰 수·비용만.
- 브라우저의 썸네일은 시트를 닫으면 사라지는 메모리 상태 (localStorage 에 넣지 않음).
- Anthropic API 로는 전송된다 (API 데이터 보존 정책을 따름) — 개인정보 처리방침에 "사진 인식 시 외부 AI 로 전송, 서비스는 저장하지 않음" 문구 필요.

**한계·다음**
