# 🥗 식이 조건 태깅 기준 v1

> 로드맵 P2 "식이 조건 태깅 기준 문서 (비건/채식/할랄/글루텐/유제품/견과/갑각류) — 태깅 가이드 + 신뢰도 레벨 정의".
> 검수자(s07 검수 시트)가 180개 음식에 **같은 기준**으로 값을 넣기 위한 문서. 앱은 이 값을 그대로 배지로 그리고, AI 는 이 값을 해설만 한다 (04 문서 §5-②).

## 1. 신뢰도 4단계 (`diet_level`)

| 값 | 화면 | 푸디가 하는 말 | 언제 쓰나 | 출처 조건 |
|---|---|---|---|---|
| `yes` | ✓ 초록 | "가능한 음식이에요" | **대표 조리법**에 해당 조건을 깨는 재료가 없다 | **서로 다른 출처 2개 이상** (s07 이 자동 강제) |
| `depends` | ! 노랑 | "조리법에 따라 달라요, 주문할 때 확인" | 대표 조리법에도 변형이 흔하다 (젓갈 유무, 기 사용, 밀가루 혼합 등) | 1개 이상 + `diet_note` 에 **무엇이 달라지는지** 한 문장 |
| `no` | ✕ 빨강 (상세 표에서만) | "맞지 않는 음식이에요" | 대표 조리법의 **주재료**가 조건을 깬다 | **2개 이상** |
| `unknown` | ? 회색 | "아직 확인되지 않았어요" | 근거 부족. **검수 전 기본값** | — |

- 추천 필터는 `yes`·`depends` 를 통과시킨다 (match_foods RPC). 그래서 **depends 에는 반드시 diet_note** 가 있어야 사용자가 판단할 수 있다.
- 출처가 부족한 `yes`/`no` 는 s07 import 단계에서 자동으로 `unknown` 으로 강등된다.
- 앱 사용자 신고 3건이 쌓이면 해당 필드는 자동으로 `unknown` (DB 트리거 `demote_on_reports`). 검수자가 다시 확인해 복구한다.

## 2. 조건별 판정 규칙

"대표 조리법" = 그 나라에서 가장 흔한 형태 (위키백과 본문·관광청 소개 기준). 식당 한 곳의 변형으로 판정하지 않는다.

| 조건 | `no` 가 되는 재료 (주재료일 때) | 흔한 `depends` 사유 | 주의 |
|---|---|---|---|
| **비건** | 고기·생선·해산물, 달걀, 우유·버터·**기(ghee)**·치즈·요거트, 꿀, 젓갈·피시소스·멸치육수, 젤라틴, 동물성 육수 | 젓갈·피시소스를 넣는 집과 안 넣는 집 / 기 vs 식물성 기름 | 양념·육수에 숨은 동물성 재료가 가장 흔한 오류 |
| **채식** (락토·오보) | 고기·가금류·생선·해산물, 동물성 육수, 젓갈·피시소스, 젤라틴 | 고기 육수 사용 여부 | 달걀·유제품은 허용 |
| **할랄** | **돼지고기**·돼지 지방·라드, 알코올(술로 조리·숙성) | **육류가 들어가면 최소 depends** (도축 방식은 식당마다 다르다) | 할랄은 재료만이 아니라 도축·조리 과정 문제. 우리는 "할랄 인증"을 판정하지 않고 **재료 기준 적합성**만 표기 — diet_note 에 그렇게 적는다 |
| **글루텐 프리** | 밀·보리·호밀 (밀가루 피·면·빵, 맥주) | **간장**(대부분 밀 포함), 튀김옷, 밀가루를 섞는 반죽(인제라 등), 같은 기름 튀김 | 교차 오염은 판정 불가 → depends + note |
| **유제품 없음** | 우유·크림·버터·기·치즈·요거트·파니르 | 버터 마무리 여부, 기 vs 식물성 기름 | |

### 알레르기 (`allergens[]`, 9종)
`nuts`(견과류) · `peanut`(땅콩) · `shellfish`(갑각류) · `fish`(생선) · `egg` · `soy` · `wheat` · `dairy` · `sesame`

- **대표 조리법의 주재료·양념에 들어가면 표기**한다. 선택 재료(role=optional)는 표기하지 않고 diet_note 에 쓴다.
- 앱은 사용자가 고른 알레르기가 하나라도 있는 음식을 **추천에서 완전히 뺀다** (depends 개념 없음 — 알레르기는 안전 쪽으로).
- 온보딩은 견과류·갑각류·땅콩을 먼저 묻고(02 문서 M3), 나머지는 Passport 설정에서 고른다.

## 3. 재료 플래그와 자동 모순 검사 (s07)

LLM 초안의 재료에는 `animal_origin`, `pork`, `allergen`, `category`, `role` 이 붙는다. s07 이 아래 모순을 **export 때 경고, import 때 차단**한다.

| 모순 | 예 |
|---|---|
| 동물성 주재료인데 vegan=yes | 젓갈 김치를 비건 yes |
| 육류·해산물 주재료인데 vegetarian=yes | |
| 돼지고기 포함인데 halal≠no | 레촌 halal=depends |
| 유제품 주재료인데 dairy_free=yes | |
| 밀 주재료인데 gluten_free=yes | |

## 4. 검수 시트 작성법 (`data/draft/review_sheet.csv`)

1. `draft_*` (LLM 초안)과 `diet_reason` 을 읽는다 — 초안은 참고일 뿐, 그대로 옮기지 않는다.
2. `final_vegan` … `final_dairy_free` 에 `yes / depends / no / unknown`.
3. `diet_sources` 에 근거 URL 을 공백으로 구분해 넣는다. **yes·no 는 2개 이상**. 우선순위: 공식 관광·문화 기관 > 학술·백과 > 음식 매체 (04 문서 §6).
4. depends 면 `diet_note` 에 **사용자가 주문할 때 확인할 것**을 해요체 한 문장으로: "젓갈을 넣는 경우가 많아요. 비건 김치는 따로 확인하세요."
5. 모르면 `unknown`. **틀린 yes 보다 unknown 이 낫다.**
6. `approve=Y`, `reviewer` 에 이름. 작성자와 검수자는 다른 사람 (07 문서 거버넌스).
