## 1. 데모 모드 — "현장에서 무엇이 죽어도 데모 10문항은 돈다"

| 무엇이 죽나 | 대응 | 어디서 |
|---|---|---|
| AI·DB·서버 전부 / 현장 와이파이 | **데모 팩**: 10문항 답을 발표 전에 실제 파이프라인으로 만들어 발표 기기 브라우저(Cache Storage)에 저장 | `/demo` ① |
| TTS | 10문항 음성을 미리 만들어 같은 곳에 저장. 없으면 브라우저 음성 | `/demo` ② |
| 화면 이동 (상세·Passport·국가) | **서비스 워커**가 화면 HTML·JS·글꼴을 저장해 두고 네트워크가 끊기면 꺼내 준다 | `/demo` ③, `public/sw.js` |
| 마이크 권한·음성 인식 | 리허설 때 미리 허용. 그래도 안 되면 `/demo` 의 질문 버튼을 탭 (= 같은 답) | `/demo` ④ |

### 동작 방식
- **데모 모드 켜짐**: 10문항은 팩에서 즉시 답한다 (네트워크 0, 지연 0). 그 밖의 질문은 평소대로 서버로.
- **데모 모드 꺼짐 (평소)**: 서버가 실패하면 **그때만** 팩에서 찾고, 답 위에 "📦 연결이 불안정해 저장된 답으로 보여드려요"를 띄운다. 팩에 없는 질문은 "인터넷 연결이 끊겼어요".
- **매칭**: 음성 인식 결과는 대본과 글자 그대로 같지 않다 ("오늘 어디로 떠나 볼까"). 띄어쓰기·호출어·어미를 지우고 글자 2-gram 유사도 0.72 이상 **+ 핵심어(국가·음식·식이·장소) 일치**를 요구한다. 핵심어 조건이 없으면 "목성 음식 추천해줘"가 "화성" 답(유사도 0.80)을 튼다.
- **맥락 질문**(#4 팔라펠, #6 만두)은 같은 음식 화면에서만 매칭.
- **Passport 질문**(#7)은 녹화된 숫자를 틀지 않고 발표 기기의 실제 탐험 기록으로 다시 계산한다.
- 팩 질문 = 할루시네이션 테스트 셋 D01~D10 과 **같은 목록** (`lib/foodi/eval/cases.ts`). 테스트한 질문과 무대 질문이 어긋나지 않는다.

### `/demo` 발표자 페이지 (일반 메뉴에 없음)
리허설 체크리스트 🟢🟡🔴: 서버·키 / 데모 팩(문항 수·실데이터 여부·생성 시각) / 미리 만든 음성 / 오프라인 화면(서비스 워커·저장 수) / 마이크 권한 / 음성 인식 방식.
버튼: ① 데모 팩 만들기 ② 음성 미리 만들기 ③ 오프라인 준비 ④ 마이크 권한 · 데모 모드 스위치 · 무대용 질문 10개 · 인트로 다시 보기 · **첫 방문 상태로 초기화**(리허설 반복용) · 팩 JSON 백업.

### 발표 당일 순서 (리허설 3회 이상, 06 문서 §6)
1. 발표 기기에서 실제 키·DB 로 `/demo` → ①②③④ 모두 🟢
2. 데모 모드 켬 → "첫 방문 상태로 초기화" → 홈에서 인트로부터 리허설
3. 비행기 모드로 한 번 더 리허설 (오프라인 경로 확인)
4. 백업 영상은 별도 준비 (이 기능이 대체하지 않음)

### 검증 (2026-10-01, 프로덕션 빌드 + 헤드리스 Edge)
서비스 워커 작동 → 데모 팩 10문항 저장 → 화면 29개 저장 → **네트워크 차단** → 팔라펠 상세 열림 → "오늘 어디로 떠나 볼까"(대본과 다른 말투) → 저장된 답 + 안내 표시. 매칭 단위 테스트 13개(말투 변형 6 · 오매칭 금지 4 · 맥락 3).

### 보안·비용
`/api/demo/pack` 은 LLM 을 10번 부른다 → 운영 환경에서는 `DEMO_MODE=true` 일 때만 열리고, 분당 3회 제한.
