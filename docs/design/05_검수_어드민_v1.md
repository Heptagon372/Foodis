# 🛠️ 콘텐츠 검수 어드민 v1 (F-ADM-01~04)

> 로드맵 P2 "콘텐츠 검수 어드민 — CRUD · CSV 업로드 · verified 플로우" (P0, "데이터 입력 시작 전에 최소 버전 필요").
> 원칙: **"DB가 사실의 기준"은 검수 도구가 있어야 실제로 지켜진다** (07 문서 §4). 발표에서 검수 화면 캡처 1장이 신뢰성 주장의 증거.

## 1. 시작하기

1. Supabase SQL Editor 에서 `supabase/migrations/0001_init.sql` → `0002_data_sources.sql` 실행
2. `apps/web/.env.local` 의 `ADMIN_EMAILS=` 에 팀장 메일 (쉼표로 여러 명). 서버 재시작 (콘솔 `R`)
3. `/admin` (콘솔 `A`) → 이메일 입력 → 메일의 링크 클릭 또는 6자리 코드 입력
4. 대시보드 **국가 30개 동기화** → **가져오기**에 검수 시트 업로드 → **검수 대기** 목록에서 검수

다른 팀원 권한은 SQL 로: `insert into admin_roles (user_id, role) values ('<auth.users id>', 'reviewer');` (editor · reviewer · admin)

## 2. 화면

| 화면 | 경로 | 하는 일 |
|---|---|---|
| 로그인 | `/admin/login` | Supabase 이메일 OTP. 기본 메일은 링크만 오므로 링크 콜백(`/admin/auth/callback`)도 지원 |
| 대시보드 | `/admin` | 앱이 실제 DB 인지 샘플인지 · 국가·음식 검수율·임베딩·열린 신고·AI 검증 실패·오늘 비용. 국가 동기화 · 임베딩 만들기 |
| 음식 | `/admin/foods` | 검수 대기 먼저. 상태·국가·검색 필터, 식이 5색 점, 신고 수 |
| 편집·검수 | `/admin/foods/[id]` | 전 필드 편집, 식이 4단계 버튼, 알레르기, 식이 출처 URL, 근거 자료 링크, 열린 신고. 규칙 위반은 저장 전에 표시 |
| 신고 큐 | `/admin/reports` | 열림·해결·반려. 같은 음식·식이 필드 신고 3건이면 DB 트리거가 그 값을 미확인으로 강등 |
| 가져오기 | `/admin/import` | s07 `review_sheet.csv` → 미리보기(새로·갱신·건너뜀·오류) → 저장. 전부 검수 대기 |
| AI 로그 | `/admin/logs` | 푸디 답변 기록, 검증 실패→템플릿 필터, 응답 지연 p95 |

## 3. 검수 규칙 (서버에서 강제 — `lib/admin/rules.ts`, 테스트 7개)

| 규칙 | 근거 |
|---|---|
| 내용을 저장하면 **검수가 풀리고**, 저장한 사람이 작성자가 된다 | 고친 내용은 다시 확인돼야 노출 |
| **작성자 ≠ 검수자.** editor 는 승인 불가, 본인 작성은 승인 불가 | 07 거버넌스 "작성자와 검수자 분리" |
| admin 만 본인 작성 **예외 승인** (확인창 + 서버 로그) | 1~2인 팀 현실 |
| 식이 확정값(yes/no)은 **서로 다른 출처 URL 2개 이상** | 04 §6 · s07 과 동일 |
| depends 면 diet_note 필수, 비건 yes → 채식 yes, 알레르기(유제품·밀·달걀·생선·갑각류)와 식이 모순 차단 | 03 태깅 기준 |
| 가져오기는 사람이 적은 `final_*` 만 — AI 초안 `draft_*` 식이는 버림 | 식이 정보 생성 금지 (04 §5-②) |
| summary 없으면 승인 불가 | 푸디가 읽을 문장이 필요 |

출처는 0002 데이터 소스 레지스트리에 연결: 식이 출처 → `foodis_review`, 가져온 설명 → `foodis_llm_draft`.

## 4. 사용자 신고 (F-ADM-03 앞단)
상세 화면 식이 탭 "정보가 틀렸나요?" → 항목 선택(비건·할랄·알레르기·설명·기원…) + 메모 → `/api/reports`. 게스트도 가능, 남용 방지로 IP·사용자별 분당 3회·하루 10회. 미리보기 모드에서는 저장하지 않음.

## 5. 보안
- `/admin`·`/api/admin/*` 는 서버에서 역할 확인 후에만 service_role 사용. 미들웨어는 어드민 경로에서만 세션 쿠키 갱신
- 로그인 없이 접근: 화면은 로그인으로 이동, API 는 401 (확인함)

## 6. 검증 상태 (2026-10-01)
- 규칙·CSV·임베딩 텍스트 단위 테스트 7개, 전체 앱 테스트 65개 통과 · 타입체크·린트 통과
- 비로그인 차단, 로그인 화면, 신고 API(미리보기) 확인
- **실제 로그인·승인·가져오기는 미검증** — Supabase 에 테이블이 아직 없고, 외부 서비스(Supabase Auth)에 테스트 계정을 대신 만들 수 없어서. 팀장이 1회 로그인해 확인 필요
