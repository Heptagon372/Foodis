# 🔐 회원 로그인 · 게스트 기록 동기화 v1 (F-AUTH-01·02)

> 07 문서 F-AUTH-01(소셜 로그인, P0) · F-AUTH-02(게스트 → 회원 전환, P1) 구현 기록.
> 원칙: **로그인은 선택**. 둘러보기·푸디·Passport·식이 필터는 로그인 없이 브라우저 저장으로 전부 된다. 로그인은 "기록을 잃지 않게 + 다른 기기에서 이어서" 를 위한 것.

## 1. 화면

| 화면 | 경로 | 파일 | 내용 |
|---|---|---|---|
| 로그인 | `/login?next=` | `components/LoginView.tsx` | 카카오(#FEE500) · Google · 이메일 6자리 코드. 지금까지 모은 "N개국 · N개 음식도 옮겨져요" 안내. "로그인 없이 계속 둘러보기" 항상 노출. 탭 바 숨김 |
| 콜백 | `/auth/callback` | `app/auth/callback/route.ts` | OAuth `?code=` · 이메일 링크 `?token_hash=` 둘 다. `next` 는 같은 사이트 경로만 (오픈 리다이렉트 방지) |
| Passport 계정 | `/passport` 하단 "계정" | `components/AccountCard.tsx` | 게스트: 로그인 권유 / 회원: 제공자·메일, 저장 상태(저장하는 중 · 계정에 저장됨 · 실패 · 미리보기), 로그아웃, 탈퇴(2단계 확인) |
| 권유 한 줄 | `/passport` 요약 아래 | `AccountNudge` | 게스트 + 음식 3개 이상일 때만 |

- **켜진 로그인 방식만 버튼으로**: Supabase 공개 설정(`/auth/v1/settings`)을 읽어 꺼진 제공자는 숨긴다. 꺼진 제공자를 누르면 Supabase 의 JSON 오류 화면으로 가 버리기 때문. 확인 전에는 버튼을 그리지 않아 깜빡임이 없다
- Supabase 원문 오류는 사람 말로 바꾼다 (`friendly()`): 제공자 꺼짐 · 메일 1분 제한 · 코드 만료 · 취소

## 2. 동기화 규칙 — `lib/account/merge.ts` (테스트 `merge.test.ts`)

| 시점 | 모드 | 탐험 기록 | 식이·알레르기·취향 |
|---|---|---|---|
| 이 기기에서 그 계정으로 처음 로그인 | `merge` | 이 기기 ∪ 계정 (가장 이른 탐험 시각 유지) | **합집합** — 비건 조건이 한쪽에만 있어도 남긴다 (더 엄격한 쪽이 안전) |
| 그 뒤 로컬이 바뀔 때 (1.5초 모아서) | `push` | **바뀐 음식만** 보낸 상태 그대로 덮어쓰기 (좋아요 취소 반영). 안 보낸 음식은 그대로 — 다른 기기 기록을 지우지 않는다 | 바뀌었을 때만 보낸 값으로 |
| 앱 첫 로드 · 1분 넘게 떠났다 돌아올 때 | `push` | 바뀐 게 없어도 1번 호출 → 응답(계정 전체)으로 다른 기기 기록을 받아 온다 | 〃 |

- 응답은 항상 **계정의 전체 상태**. 요청을 보낸 뒤 이 기기에서 또 바뀐 음식은 로컬 값을 지키고 다음 push 로 올린다
- "무엇이 바뀌었나" 는 `localStorage["foodis:account"]` 에 마지막으로 맞춘 상태의 서명(uid · 음식별 상태 · 식이)으로 판단
- 탐험 기록이 있는 음식은 최소 `explored` 를 유지 (좋아요만 꺼도 탐험 국가에서 빠지지 않게)
- DB 에 없는 음식 id(미리보기 샘플)는 서버가 버리고 이 기기에만 남는다. 미리보기 모드(검수된 음식 0개)에서는 409 `not_live` → "이 기기에만 저장돼요"
- Food DNA 는 서버가 같은 가중치(좋아요 2 · 먹어봤어요 1.5 · 탐험 1 · 온보딩 취향 1)로 다시 계산해 `food_dna` 에 저장

## 3. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/me/sync` | `{ mode, prefs?, entries[] }` → `{ prefs, entries[] }`. 본인 확인은 세션 쿠키, 쓰기는 service_role 로 user_id 고정. 분당 30회 |
| GET | `/api/me` | 로그인 여부 |
| DELETE | `/api/me` | 회원 탈퇴 — `auth.users` 삭제 → profiles·dietary_profiles·passport_entries·food_dna 연쇄 삭제, reports 는 user_id 만 비움 |

DB: `supabase/migrations/0003_user_sync.sql` — `profiles.tastes · onboarded · updated_at`, Passport 인덱스.

## 4. 개인정보 결정

- **로그아웃하면 이 기기의 개인 기록(탐험·식이·취향)을 지운다** — 기록은 계정에 있고, 공용 기기에서 다음 사람에게 남지 않게. 인트로·온보딩 완료 여부는 남긴다
- 탈퇴는 되돌릴 수 없다는 문구 + 2단계 확인. 로그인 화면에도 "언제든 탈퇴하면 모두 지워져요"
- 식이 조건은 추천 필터에만 쓰이고 본인 계정에만 저장 (Passport 문구도 로그인 여부에 따라 "이 기기에만 / 내 계정에만")

## 5. 설정 (사람이 할 일)

1. SQL Editor 에서 `0001` → `0002` → `0003`
2. Authentication → URL Configuration → Redirect URLs: `http://localhost:3000/auth/callback` (+ 배포 주소)
3. (선택) Authentication → Providers → Kakao / Google 켜기. 카카오는 개발자 콘솔에서 Redirect URI `https://<프로젝트>.supabase.co/auth/v1/callback`, 동의 항목(닉네임·프로필 사진, 이메일은 비즈 앱 필요)
4. 켜면 로그인 화면에 버튼이 자동으로 나타난다
