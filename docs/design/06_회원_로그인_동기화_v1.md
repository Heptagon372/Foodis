# 🔐 회원 로그인 · 게스트 기록 동기화 v1 (F-AUTH-01·02)

> 07 문서 F-AUTH-01(소셜 로그인, P0) · F-AUTH-02(게스트 → 회원 전환, P1) 구현 기록.
> 원칙: **로그인은 선택**. 둘러보기·푸디·Passport·식이 필터는 로그인 없이 브라우저 저장으로 전부 된다. 로그인은 "기록을 잃지 않게 + 다른 기기에서 이어서" 를 위한 것.

## 2. 동기화 규칙 — `lib/account/merge.ts` (테스트 `merge.test.ts`)

| 시점 | 모드 | 탐험 기록 | 식이·알레르기·취향 |
|---|---|---|---|
| 이 기기에서 그 계정으로 처음 로그인 | `merge` | 이 기기 ∪ 계정 (가장 이른 탐험 시각 유지) | **합집합** — 비건 조건이 한쪽에만 있어도 남긴다 (더 엄격한 쪽이 안전) |
| 그 뒤 로컬이 바뀔 때 (1.5초 모아서) | `push` | **바뀐 음식만** 보낸 상태 그대로 덮어쓰기 (좋아요 취소 반영). 안 보낸 음식은 그대로 — 다른 기기 기록을 지우지 않는다 | 바뀌었을 때만 보낸 값으로 |
| 앱 첫 로드 · 1분 넘게 떠났다 돌아올 때 | `push` | 바뀐 게 없어도 1번 호출 → 응답(계정 전체)으로 다른 기기 기록을 받아 온다 | 〃 |

- 응답은 항상 **계정의 전체 상태**. 요청을 보낸 뒤 이 기기에서 또 바뀐 음식은 로컬 값을 지키고 다음 push 로 올린다
- "무엇이 바뀌었나" 는 `localStorage["foodis:account"]` 에 마지막으로 맞춘 상태의 서명(uid · 음식별 상태 · 식이)으로 판단
- 탐험 기록이 있는 음식은 최소 `explored` 를 유지 (좋아요만 꺼도 탐험 국가에서 빠지지 않게)
- DB 에 없는 음식 id(미리보기 샘플)는 서버가 버리고 이 기기에만 남는다. 미리보기 모드(검수된 음식 0개)에서는 409 `not_live` → "이 기기에만 저장돼요"
- Food DNA 는 서버가 같은 가중치(좋아요 2 · 먹어봤어요 1.5 · 탐험 1 · 온보딩 취향 1)로 다시 계산해 `food_dna` 에 저장

## 4. 개인정보 결정

- **로그아웃하면 이 기기의 개인 기록(탐험·식이·취향)을 지운다** — 기록은 계정에 있고, 공용 기기에서 다음 사람에게 남지 않게. 인트로·온보딩 완료 여부는 남긴다
- 탈퇴는 되돌릴 수 없다는 문구 + 2단계 확인. 로그인 화면에도 "언제든 탈퇴하면 모두 지워져요"
- 식이 조건은 추천 필터에만 쓰이고 본인 계정에만 저장 (Passport 문구도 로그인 여부에 따라 "이 기기에만 / 내 계정에만")

## 7. 인스타그램 로그인 · 계정 연결 (v1.1)

> 요청: "계정은 구글, 카카오, 인스타 되도록 연동할 수 있도록" — 세 방법 중 무엇으로든 로그인하고, 한 FOODIS 계정에 여러 방법을 붙였다 뗐다 할 수 있게.
> Supabase 에는 인스타그램 제공자가 없다 (Meta 의 Instagram Basic Display API 는 2024-12 종료 — 남은 것은 "Instagram API with Instagram Login" = 인스타그램 비즈니스 로그인). 그래서 인스타만 OAuth 를 우리 서버가 직접 돈다.

### 7.2 인스타그램 흐름

1. **시작** `/auth/instagram?mode=login|link&next=/경로` — 무작위 state(24바이트) + mode + next (+ 연결이면 지금 회원 id)를 앱 시크릿 HMAC 으로 서명한 쿠키 `foodis_ig_state`(httpOnly · SameSite=Lax · path `/auth/instagram` · 10분)에 담고 `https://www.instagram.com/oauth/authorize?client_id…&redirect_uri…&response_type=code&scope=instagram_business_basic&state…` 로 보낸다. 연결은 로그인한 회원만 (아니면 `/login`)
2. **콜백** `/auth/instagram/callback` — 쿠키 서명 · 만료 · 주소의 state 일치를 확인하고 바로 지운다(1회용) → `POST https://api.instagram.com/oauth/access_token` (응답이 평평한 `{access_token, user_id}` 이든 `{data:[…]}` 이든 받는다. 17자리 id 가 숫자로 오면 `JSON.parse` 가 끝자리를 잃어서 원문에서 숫자 그대로 뽑는다) → `GET https://graph.instagram.com/me?fields=user_id,username,name,profile_picture_url` (실패하거나 필드가 빠져도 id 만으로 진행). 신원 키 = 토큰의 `user_id` (없으면 `/me` 의 `id`)
3. **로그인** — `social_links(instagram, id)` 가 있으면 그 회원. 없으면 `admin.createUser({ email: instagram-<id>@users.foodis.invalid, email_confirm, user_metadata: { name, user_name, avatar_url }, app_metadata: { foodis_provider: 'instagram' } })` 후 연결 저장 (같은 메일이 이미 있으면 — 앞선 시도가 연결 저장 전에 끊긴 경우 — 그 회원을 그대로 쓴다). 세션은 **메일 없이** 만든다: `admin.generateLink({ type: 'magiclink' })` 의 `hashed_token` 을 서버에서 바로 `verifyOtp({ token_hash, type: 'magiclink' })` → SSR 클라이언트가 세션 쿠키를 쓴다 → `next`. 게스트 기록 병합(§2)은 다른 로그인과 똑같이 다음 화면에서 돈다
   - 연결된 회원에게 메일이 없으면(이메일 동의 없이 가입한 카카오 등) 세션 발급용으로 같은 가짜 메일을 붙인다
4. **연결** — 쿠키의 회원 id 와 지금 세션 회원이 같아야 한다 → 다른 회원에 연결된 인스타면 거절("이미 다른 FOODIS 계정에 연결된 인스타그램이에요"), 이미 다른 인스타가 붙어 있으면 거절(해제 후 다시) → 저장. 프로필 사진이 없던 회원만 인스타 사진으로 채운다 → `next?linked=instagram`
5. **인스타 토큰은 저장하지 않는다** — 신원 확인 한 번에만 쓴다. 표에는 id · @아이디 · 사진 주소만
- redirect_uri 는 요청 origin + `/auth/instagram/callback`. 시작과 토큰 교환에서 글자 하나까지 같아야 해서 둘 다 `callbackUrl(origin)` 으로 만든다
- 오류는 코드(`instagram_state` · `instagram_token` · `instagram_linked_elsewhere` · `access_denied` …)로 `/login?error=` (로그인) 또는 `next?link_error=` (연결)에 실어 보내고, 화면이 `authErrorText` 로 사람 말로 바꾼다
- 콜백은 IP 당 분당 20회 (회원 생성 남용 방지)

### 7.3 연결된 계정 — 설정 → 계정

`AccountCard` 안의 `LinkedAccounts`. 카카오 · Google · Instagram 줄마다 브랜드 표시 + "연결됨 · 메일/@아이디" 또는 "연결 안 됨" + 연결 / 해제(한 번 더 확인). 돌아오면 `?linked=` · `?link_error=` 를 한 번 알려 주고 주소에서 지운다.

- 꺼진 제공자는 숨긴다 — 로그인 화면과 같은 `useAuthProviders()` (`/auth/v1/settings`, 앱에서 1번만 묻는다). 꺼졌어도 이미 연결된 것은 보인다. 인스타는 `/api/me/links` 의 `instagram` (앱 키 + service_role + 0013 표가 있을 때만 true)
- 카카오·Google 연결이 "manual linking disabled" 로 막히면 안내: Supabase → Authentication → Sign In / Providers → "Allow manual linking" 켜기
- **마지막 로그인 방법은 못 뗀다** (`canUnlink` — 서버 DELETE 도 같은 규칙으로 한 번 더):
  - 쓸 수 있는 방법 = 카카오·Google 등 신원 + 인스타 연결 + **진짜** 메일(이메일 코드 로그인). 가짜 메일은 코드를 받을 수 없어 치지 않는다
  - 카카오·Google 은 Supabase 규칙상 신원이 2개 이상일 때만 뗄 수 있다 → 가입 때 신원 하나뿐이면 "처음 가입한 로그인 방법이라 해제할 수 없어요"
  - 인스타로만 가입한 회원은 다른 방법을 붙이기 전엔 인스타를 못 뗀다. 인스타 가입 + Google 연결이면 둘 중 하나는 뗄 수 있고, 남은 하나는 못 뗀다

| 경우 | 인스타 해제 | 카카오/Google 해제 |
|---|---|---|
| 인스타로만 가입 | ✗ 마지막 방법 | — |
| 카카오 가입 + 인스타 연결 | ○ | ✗ 처음 가입한 방법 (Supabase 신원 1개) |
| 인스타 가입 + Google 연결 | ○ | ○ (인스타가 남음) |
| 위에서 인스타를 뗀 뒤 | — | ✗ 마지막 방법 (남는 건 가짜 메일뿐) |
| Google 가입(진짜 메일) + 카카오 연결 | — | ○ |

- 인스타를 뗄 때 그 인스타로 만든 계정이면 가짜 메일을 `user-<회원 id>@users.foodis.invalid` 로 바꿔 둔다 — 같은 인스타로 다시 로그인하면 해제한 이 계정이 아니라 새 계정이 된다 (해제는 해제)
- 가짜 메일(`@users.foodis.invalid`, `.invalid` 는 실제로 존재할 수 없는 도메인)은 화면 어디에도 안 보인다: `toUser`(계정 카드 · 데스크톱 내비 · 로그인 화면)와 `GET /api/me` 가 걸러 내고 이름 대신 `@아이디` 를 보여 준다. 가입 방법은 `app_metadata.foodis_provider` 로 "Instagram 로그인" 표시. 커뮤니티 이름은 `user_metadata.name` (인스타 이름 → 없으면 아이디)
- 인스타 프로필 사진 주소는 며칠 뒤 만료된다 → 계정 카드는 사진이 깨지면 첫 글자로. 연결 표의 사진·아이디는 인스타로 로그인할 때마다 새로 쓴다

### 7.4 DB — `supabase/migrations/0013_social_links.sql`

| 컬럼 | 설명 |
|---|---|
| `provider` · `provider_uid` | 기본 키 — 인스타 계정 하나는 회원 한 명에게만 |
| `user_id` | `auth.users on delete cascade` (탈퇴하면 같이 지워진다). `unique(user_id, provider)` — 회원당 제공자 하나 |
| `username` · `avatar_url` · `created_at` | 표시용 |

RLS 켜짐 — 본인 행 `select` 만. 쓰기·지우기 정책은 없다(서버 service_role 만). `if not exists` · `drop policy if exists` 라 여러 번 실행해도 안전.
