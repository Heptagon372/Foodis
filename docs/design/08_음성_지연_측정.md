- **후보 (2026-10 추가)**: 위 셋에 ElevenLabs Flash v2.5 (Talia) · NAVER CLOVA Voice Premium (vara) · Gemini TTS (Sulafat, `GEMINI_TTS_MODEL`) — 다시 돌리면 §2 표에 행이 생긴다. 사용자가 고르는 목소리 21개(제공자 5곳) 전체 · 단가 · 출처는 [design/11 목소리 카탈로그](11_목소리_카탈로그.md). 앱의 실제 체인은 "고른 목소리 → `TTS_PROVIDER` 순서 기본 체인 → 브라우저 음성".

## 6. 스트리밍 재생 (첫 음성 지연 1차 대응)

> 3초를 넘기는 첫 원인은 "MP3 를 끝까지 받은 뒤 재생" 이었다 → 첫 조각부터 재생하도록 바꿨다 (2026-10).

| 구간 | 전에는 | 지금 |
|---|---|---|
| 서버 `/api/foodi/tts` | 제공자 `synthesize()` 결과를 그대로 전달 | `stream()` 이 있으면 먼저(OpenAI `audio.speech.create` 본문을 받는 대로), 실패하면 같은 제공자 `synthesize()` → 다음 제공자 → 503. 첫 조각을 받아 본 뒤에 200 을 보낸다 (첫 조각 전 실패는 아직 되돌릴 수 있음). 헤더 `X-TTS-Mode: stream \| buffered` |
| 사용량 기록 | 응답 직전 | 첫 조각을 받은 때 — 비용이 글자 수 추정치라 미리 알고, 사용자가 중간에 끊어도 제공자는 이미 과금했으므로 완료 시 기록하면 덜 잡힌다 |
| `speak()` (푸디 답변) | `res.blob()` → `new Audio(url)` | `stream-audio.ts` `attachResponse()` — MediaSource 에 조각을 이어 붙이며 재생. 돌아오는 시점 = `playing` (= KPI `first_audio_ms`) |
| 라디오 | 구간마다 blob (다음 구간 미리 받기) | 미리 받지 않은 구간(첫 구간·넘기기 직후)만 스트리밍, 다음 구간은 첫 소리가 난 뒤 blob 으로 미리 받기. 8초 제한은 "첫 소리까지" 로 바꿈. 다 받은 스트림은 캐시에 넣어 다시 듣기는 바로 |

**브라우저 지원** (런타임에 `isTypeSupported("audio/mpeg")` 로 확인, 안 되면 예전처럼 다 받은 뒤 재생):

| 브라우저 | 경로 | 비고 |
|---|---|---|
| Chrome · Edge (데스크톱·안드로이드) | `MediaSource` | MP3 MSE 지원 |
| Firefox | `MediaSource` | MP3 MSE 지원 |
| Safari 데스크톱 · iPadOS | `MediaSource` | |
| iPhone Safari 17.1+ | `ManagedMediaSource` | `disableRemotePlayback = true` 필요(설정함). 라디오의 잠금 해제된 `<audio>` 를 그대로 쓴다 |
| iPhone Safari ≤ 17.0 · MSE 없는 인앱 브라우저 | blob (다 받은 뒤) | 이전과 같음 |

- 첫 소리 전에 디코드 오류(형식 미지원)가 나면 그 탭에서는 이후 blob 경로로 바꾼다 (이번 음성은 브라우저 음성으로 대체).
- 받는 중 끊기면(첫 조각 뒤) 받은 데까지 재생하고 정상 종료한다.
- 기대 효과: OpenAI 는 첫 음성 ≈ 첫 바이트 (§2 표의 "받는 대로 재생" 열). Google 은 서버가 한 번에 합성하므로 효과 없음 — 그대로 "전체 합성" 시간.

**Google `streamingSynthesize` 를 안 쓰는 이유:**

- 출력 형식이 PCM·ALAW·MULAW·OGG_OPUS 뿐 (MP3 불가, `StreamingAudioConfig`). Ogg 는 MediaSource 에서 Safari·Chrome 이 받지 않고, PCM 은 `<audio>` 가 아니라 Web Audio 로 직접 이어 붙여야 한다 → iOS 에서 사용자 탭으로 잠금 해제한 `<audio>` 하나를 재사용하는 라디오 구조와 맞지 않는다. 서버에서 MP3 로 다시 인코딩하려면 인코더(ffmpeg·lame wasm)를 서버리스 함수에 실어야 한다.
- Chirp 3 HD 음성 전용 → 현재 기본(Wavenet)에는 못 쓴다. gRPC 양방향 스트림이라 요청마다 연결 비용도 붙는다.
- Google 을 고른다면 대안: 첫 문장만 먼저 `synthesizeSpeech` 해 흘려보내고 나머지를 이어 붙이기(MP3 프레임은 이어 붙여도 재생된다), 또는 데모 10문항 음성 미리 만들기(데모 팩).

**측정:** `/demo` "지연 측정" 패널에 "서버 TTS · 받는 대로" / "서버 TTS · 다 받고" 버튼이 따로 있다 → 같은 기기에서 두 방식을 비교해 §3 에 붙인다. 서버 측은 `pnpm --filter web bench:voice` (§2).
