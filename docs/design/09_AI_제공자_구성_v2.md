## 1. 결론

| 무엇 | 결정 | 이유 |
|---|---|---|
| 1순위 LLM | **Gemini 3.5 Flash-Lite** (의도·답변·사진 모두) | $0.30 / $2.50. Sonnet 5 대비 답 1건 비용 약 1/5. 안정(stable) 모델, thinking 기본값이 `minimal` 이라 음성 지연에 맞다 |
| 2순위 LLM (장애 대체) | **GPT-6 Luna** (의도·답변·사진 모두) | $0.10 / $0.50 — 가장 싸다. reasoning `none` 지원 → 생각 토큰 없이 바로 답 |
| 선택 LLM | Anthropic (Haiku 4.5 · Sonnet 5) | `LLM_PROVIDERS` 에 `anthropic` 을 넣을 때만. 예전 설정 이름도 그대로 읽는다 |
| 임베딩 | 기본 **OpenAI text-embedding-3-small** 유지, `EMBED_PROVIDER=gemini` 로 **gemini-embedding-2** (1536차원) 선택 가능 | 바꾸면 전체 재생성이 필요해서 기본값은 그대로 둔다 |
| 사용자 선택 | 설정 "푸디의 두뇌"에서 모델을 고를 수 있다 (§8) | premium 모델은 예산 80% 를 넘으면 기본 모델로 내려간다 |

하루 1,000문항이면 LLM 비용은 **Anthropic 기본 약 $8.3 → Gemini 기본 약 $1.6** (GPT 만 쓰면 약 $0.4). 지금 일일 예산 `DAILY_BUDGET_USD=5` 로는 Anthropic 기본 구성이 하루 600문항쯤에서 템플릿 모드로 떨어졌다.

## 2. 티어별 모델

| 티어 | 쓰는 곳 | Gemini (1순위) | OpenAI (2순위) | Anthropic (선택) |
|---|---|---|---|---|
| fast | 의도 분류 (`intent.ts`, 규칙이 못 정할 때만) · 사진 인식 기본 | `gemini-3.5-flash-lite`, thinking `minimal` | `gpt-6-luna`, effort `none` | `claude-haiku-4-5` |
| smart | 답변 생성 (`generate.ts`) | `gemini-3.5-flash-lite`, thinking `minimal` | `gpt-6-luna`, effort `none` | `claude-sonnet-5`, effort `low` |
| vision | 사진 인식 (`vision.ts`) | 비우면 fast | 비우면 fast | 비우면 fast |

- fast·smart 가 같은 모델인 이유: 답변 작업은 "후보 안에서 고르고 DB 사실만 해설"하는 좁은 작업이고, 검증(`validate`) → 1회 재생성 → DB 템플릿이라는 방어선이 이미 있다. 더 큰 모델은 비용·지연만 늘린다. 품질이 모자라면 `LLM_GEMINI_SMART=gemini-3.6-flash` (thinking `minimal` 지원) 로 올린다 — 답 1건 비용 약 2배(2027년부터 4배).
- `gemini-3.1-flash-lite` ($0.25/$1.50) 는 더 싸지만 thinking 문서 표에 단계가 나오지 않아(같은 계열 `-image` 만 minimal·high) 기본값에서 뺐다.
- `gemini-3.8-flash` 는 가장 똑똑한 Flash 지만 `minimal` 이 없어(최소 `low`) 생각 토큰만큼 첫 음성이 늦다. 어댑터가 `minimal` 을 자동으로 `low` 로 올려 오류는 나지 않는다.
- GPT-6.1 Sol · GPT-6 Astra 는 `none`(Sol 은 `minimal` 도) 을 받지 않는다 → 어댑터가 `low` 로 올린다.

## 4. 비용 추정

가정 (측정 전 어림): 답변 호출 = 입력 2,500 · 출력 250 토큰 (문화 이야기는 출력 ~600), 의도 LLM = 입력 500 · 출력 60 토큰이고 질문의 절반만 LLM 을 탄다 (나머지는 규칙), 재생성 5%. 캐시 적중은 빼고(보수적) 계산.
`질문 1건 = 1.05 × 답변 + 0.5 × 의도`

| 구성 | 답변 1회 | 질문 1건 | 하루 1,000문항 | $5 예산으로 하루 |
|---|---|---|---|---|

| GPT 만 (`LLM_PROVIDERS=openai`) (Luna × 2) | $0.00038 | $0.00043 | $0.43 | 약 11,600문항 |
| Gemini 3.6 Flash 답변 + Flash-Lite 의도 (2026) | $0.0028 | $0.0031 | $3.10 | 약 1,600문항 |
| 〃 (2027-01-01 이후) | $0.0056 | $0.0061 | $6.06 | 약 820문항 |
| 이전 Anthropic 기본 (Haiku 4.5 + Sonnet 5) | $0.0075 | $0.0083 | $8.28 | 약 600문항 |

- 사진 인식 1장 (음식 목록 시스템 프롬프트 ~4,000 + 이미지 ~1,000 토큰 입력, 출력 150): Gemini Flash-Lite 약 $0.0019 · Luna 약 $0.0006 · (이전) Haiku 4.5 약 $0.0058.
- 질의 임베딩: 1건 ~30토큰 → OpenAI $0.0000006, Gemini $0.000006. 무시할 수준.
- GPT 만 쓰면 Gemini 기본보다 3.7배 싸다. 그래도 Gemini 를 1순위로 둔 이유: 운영자 결정(기본 `gemini,openai`)이고, 두 회사를 서로의 장애 대체로 둔다. 품질은 아직 같은 30문항으로 비교하지 못했다 (§12) — 측정 후 순서를 바꾸는 건 환경변수 한 줄이다.

## 5. 지연 (음성 예산: 답변 생성 1.5초, 11 문서 §4)

- 두 1·2순위 모델 모두 각 회사가 "저지연·대량 처리"용으로 내놓은 모델이고, 생각 단계를 끈다(`minimal` / `none`). 생각 토큰이 없으면 지연은 첫 토큰 + 출력 ~250토큰 생성 시간이다.
- 요청 타임아웃: fast 4초 · smart 6초 · 사진 12초 (`LLM_TIMEOUT_MS`). SDK 자체 재시도는 끈다 — 장애면 기다리지 않고 다음 제공자로 넘기는 편이 음성에 낫다.
- 최악의 경우(1순위가 타임아웃 → 2순위가 답)는 6초 + α 로 예산을 넘는다. 그래서 실패한 제공자는 **30초 동안 순서 맨 뒤**로 보낸다 — 장애 중 매 질문마다 타임아웃을 다시 기다리지 않는다.
- 생각 여유: thinking/reasoning 단계가 오르면 출력 한도에 여유를 더한다 (minimal +256, low +1,024 …). 쓰지 않은 한도는 청구되지 않는다.
- **실측 전**: 키가 없어 지연을 재지 못했다. 키를 넣고 `pnpm --filter web bench:voice` (08 문서) 와 `eval:live` 로 확인해야 한다.

## 6. 제공자별 API (확인한 형식)

| | Gemini (`@google/genai` 2.26) | OpenAI (`openai` 7.25, Responses API) | Anthropic (`@anthropic-ai/sdk`) |
|---|---|---|---|
| 호출 | `models.generateContent` | `responses.create` | `messages.parse` |
| 구조화 출력 | `config.responseMimeType: "application/json"` + `config.responseJsonSchema` (zod v4 `z.toJSONSchema`, `$schema` 키 제거). `responseSchema`(OpenAPI 부분집합)는 쓰지 않는다 | `text.format = zodTextFormat(schema, "foodi_output")` (strict JSON Schema) | `output_config.format = zodOutputFormat(schema)` |
| 출력 검증 | 세 어댑터 모두 받은 JSON 을 **zod 로 다시 검증** — 위반이면 `LLMOutputError` (retryable=false) | 〃 | 〃 (SDK 파싱) |
| 생각 조절 | `thinkingConfig.thinkingLevel` (MINIMAL·LOW·MEDIUM·HIGH) | `reasoning.effort` (none·minimal·low·…) | smart 만 `effort` |
| 이미지 | `parts: [{ inlineData: { mimeType, data } }, { text }]` | `input_image` + `data:` URL, `detail: "auto"` | base64 image 블록 |
| 사용량 | `usageMetadata.promptTokenCount` · `candidatesTokenCount` · `thoughtsTokenCount` | `usage.input_tokens` (+`cached_tokens`) · `output_tokens`(생각 포함) | `usage.input_tokens` · `output_tokens` |
| 저장 | generateContent 는 서버에 대화 상태를 남기지 않는다 | `store: false` | 기본 |
| 출력 오류 | `promptFeedback.blockReason`, `finishReason` ≠ STOP (MAX_TOKENS·SAFETY…) | `status: "incomplete"`, `refusal` 파트 | `stop_reason` refusal · max_tokens |

- Gemini 문서 예시는 Interactions API(`interactions.create`)로 옮겨 갔지만 SDK README 기준 `generateContent` 도 계속 지원된다. generateContent 를 고른 이유: 상태 없음(사진 저장 금지 원칙), 타입이 완비돼 있다.
- 우리 출력 스키마(IntentOutput · GenerateOutput · VisionOutput)는 객체·배열·enum·`["string","null"]`·description 만 쓴다 — Gemini `responseJsonSchema` 지원 목록과 OpenAI strict 규칙(모든 필드 required, `additionalProperties: false`) 안에 있다. 새 스키마에 `.default()`·`.optional()`·정규식 등을 쓰면 두 회사 제약을 먼저 확인할 것.
- 프롬프트(`prompts/answer.v1.ts` · 의도 SYSTEM · 사진 SYSTEM)는 XML 태그(`<candidates>` 등)로 데이터를 구분할 뿐 Claude 전용 기능(prefill·tool_use 등)에 기대지 않는다 — 세 회사에 그대로 쓴다. JSON 형식은 스키마가 강제하므로 프롬프트에 형식 지시를 넣지 않았다.

### 오류 → 재시도 판단

| 상황 | ProviderError.retryable | 체인 동작 |
|---|---|---|
| 429 · 408 · 5xx · 연결 끊김 · 타임아웃(AbortError) | true | 다음 제공자, 30초 쉬기 |
| 400 · 401 · 402(선불 소진) · 403 · 404 (설정·키·모델 이름 문제) | false | **다음 제공자**, 30초 쉬기 — 다른 회사는 독립이라 답할 수 있다 |
| 출력 오류 (`LLMOutputError`: 스키마 위반 · 거절 · 안전 차단 · 잘림) | false | **멈춤** → orchestrator 가 1회 재생성 → DB 템플릿 |
| 키 없음 | — | 호출 없이 건너뜀. 전부 없으면 `ProviderError("preview")` |

Gemini 문제 해결 문서: "Only retry on transient errors (like 429, 408, or 5xx). Do not retry on client errors (like 400, 402, or 403)".

## 7. fallback 정책 (`lib/providers/registry/llm.ts`)

1. `LLM_PROVIDERS` 순서(기본 `gemini,openai`)대로, 키 있는 제공자만.
2. 장애·설정 오류면 다음 제공자로 (위 표). 실패한 제공자는 30초 동안 순서 맨 뒤 — 전부 쉬는 중이면 원래 순서로 다 시도한다. 성공하면 쉬는 표시를 지운다.
3. **출력 오류에서는 넘기지 않는다.** 결정 이유: (a) orchestrator 의 `generate` 가 이미 같은 요청을 1회 재생성하고, 그래도 안 되면 DB 템플릿으로 답한다. (b) 다른 회사에 같은 요청을 다시 보내면 지연(음성 예산)과 비용이 두 배가 된다. (c) 거절·안전 차단은 대개 입력 내용 때문이라 회사를 바꿔도 결과가 비슷하다.
4. 전부 실패하면 마지막 `ProviderError` 를 던진다 → 의도 분류는 규칙으로, 답변은 DB 템플릿으로, 사진은 503 안내로.
5. `/api/health` 의 `providers.llm` 에 제공자별 `ready` 와 `fast · smart` 모델 이름이 보인다 (키 값은 없다). `models` 에 실행 순서.

## 8. 사용자 모델 선택 ("푸디의 두뇌")

설정(Passport → 음성 설정 맨 위)에서 사용자가 답변 모델을 고른다. 기본은 **자동(추천)** = 위 기본 체인.

| 조각 | 위치 |
|---|---|
| 선택 가능 목록(allowlist) · premium 표시 · 예산 강등 규칙 | `lib/ai/models.ts` |
| 목록 API (`ready` 는 서버 키 기준, 키 값 없음) | `GET /api/foodi/models` |
| 브라우저 저장 `{ model: string \| null }` (localStorage `foodis:ai`, 이 기기만) | `lib/client/ai-prefs.ts` |
| 고르기 화면 | `components/settings/ModelPicker.tsx` |
| 요청 | `/api/foodi/ask` 본문 `model`, `/api/foodi/vision` 본문 `model` |
| 응답 | `model_used: { id, label, provider, downgraded? }` — 답 아래 작은 글씨로 표시 |

목록 (답 1건 어림 비용 기준, 기본 두뇌보다 2배 이상 비싸면 premium):

| id | 이름 | 한 줄 | premium |
|---|---|---|---|
| gemini-3.5-flash-lite | Gemini 3.5 Flash-Lite | 빠르고 저렴한 기본 두뇌 | |
| gemini-3.6-flash | Gemini 3.6 Flash | 설명이 더 풍부해요 · 조금 느려요 | ✓ |
| gpt-6-luna | GPT-6 Luna | 가장 저렴하고 빨라요 | |
| gpt-6.1-sol | GPT-6.1 Sol | 가장 똑똑해요 · 느리고 비싸요 | ✓ |
| claude-haiku-4-5 | Claude Haiku 4.5 | 빠르고 차분한 설명 | ✓ |
| claude-sonnet-5 | Claude Sonnet 5 | 깊이 있는 이야기 · 비싸요 | ✓ |

서버 규칙:

1. **검증**: 목록에 있고 그 제공자가 켜져(`LLM_PROVIDERS`) 있고 키가 있을 때만 받는다. 모르는 값·키 없는 모델·문자열 아님 → 조용히 무시하고 자동(기본 체인). 잘못된 값으로 답을 막지 않는다.
2. **체인**: 고른 모델의 제공자를 맨 앞에 둔다. 그 제공자 안에서 답변(smart)과 사진은 고른 모델, 의도 분류(fast)는 그 제공자의 fast 모델. 실패하면 나머지 제공자가 각자 기본 모델로 이어 받는다 (§7 과 같은 규칙). `model_used` 는 **실제로 답한** 모델이라 대체가 일어나면 그대로 보인다.
3. **비싼 모델 남용 방지**: 일일 예산(`DAILY_BUDGET_USD`)은 그대로 적용된다(100% 면 모든 선택이 템플릿 모드). 오늘 사용액이 예산의 **80%** 를 넘으면 premium 선택은 기본 체인으로 내려가고 `model_used.downgraded = true` ("오늘은 사용량이 많아 기본 AI 가 답했어요"). 강등된 답은 캐시하지 않는다.
4. **캐시 분리**: 응답 캐시 키에 고른 모델 id 를 넣는다 → 다른 모델의 답이 섞이지 않는다. 자동은 예전 키 그대로라 기존 캐시가 유지된다.
5. **사진 인식**도 같은 선택·같은 규칙을 따른다.
6. 같은 규칙은 orchestrator 가 `deps.models` 를 받을 때만 켜진다 — 테스트·eval 은 선택 없이 돈다.

| 모델 (`EMBEDDING_MODEL`, 비우면 제공자 기본) | `text-embedding-3-small` | `gemini-embedding-2` (stable 2026-04) |
| 차원 | 1536 (기본) | 기본 3072 → `outputDimensionality: 1536` |
| 정규화 | 단위 벡터로 옴 | 문서: embedding-2 는 줄인 차원도 자동 정규화, embedding-001 은 3072 가 아니면 직접 정규화해야 함 → **어댑터가 항상 L2 정규화** (이미 단위면 그대로) |
| 질의/문서 구분 | 없음 | embedding-2: 질의 `task: search result \| query: {검색어}`, 문서 `title: {음식 이름 name_ko} \| text: {본문}` (제목 없으면 `none`). 001 은 `taskType` RETRIEVAL_QUERY/DOCUMENT |
| 여러 개 한 번에 | 배열 | 텍스트마다 `Content` 로 감싼다 — 문자열 배열을 그대로 주면 embedding-2 는 **하나로 합친** 벡터를 돌려준다 |
| 가격 | $0.02 / 1M | $0.20 / 1M (응답에 토큰 수가 없어 1글자≈1토큰으로 넉넉히 어림) |

**제공자를 바꾸면 임베딩을 전부 다시 만들어야 한다.** 질의 벡터와 음식 문서 벡터가 같은 모델에서 나와야 거리 비교가 의미 있다. 어드민 → 운영 작업 → **"임베딩 전체 다시 만들기"** (`onlyMissing: false`). "없는 것만"도 `food_embeddings.model` 이 지금 모델과 다른 행은 다시 만든다.

- **데이터 파이프라인과 같은 형식**: `foodis-data` s09 도 같은 환경변수(`DATA_EMBED_PROVIDER`, 비면 `EMBED_PROVIDER` · `EMBEDDING_MODEL`)와 같은 모델·차원·정규화·접두어로 만든다 — 앱의 어드민 재생성과 s09 결과가 섞여도 같은 공간이다. 문서 제목은 양쪽 모두 음식 이름(`name_ko`), 본문은 `embeddingText` / s09 `embedding_text` (같은 구성).
- **설정 불일치 가드**: `EMBED_PROVIDER=gemini` 인데 `EMBEDDING_MODEL=text-embedding-3-small` (또는 그 반대)이면 서버가 처음 뜰 때 `console.error` 로 알리고 임베딩을 끈다(키워드 검색만). `/api/health` 의 `providers.embed[].note` 에 이유가 보이고, 어드민 재생성은 412 로 막는다.

## 11. 바꾸는 법

- **GPT 를 1순위로**: `LLM_PROVIDERS=openai,gemini`
- **한 회사만**: `LLM_PROVIDERS=gemini` (그 회사가 죽으면 의도는 규칙, 답은 DB 템플릿)
- **Anthropic 을 마지막 대체로 추가**: `LLM_PROVIDERS=gemini,openai,anthropic` + `ANTHROPIC_API_KEY`
- **예전처럼 Claude 만**: `LLM_PROVIDERS=anthropic` (예전 `LLM_MODEL_*` 값 그대로 동작)
- **답변 품질 올리기**: `LLM_GEMINI_SMART=gemini-3.6-flash` 또는 `LLM_OPENAI_SMART_EFFORT=low` — 바꾼 뒤 `eval:live` · `bench:voice` 다시
- **임베딩을 Gemini 로**: `EMBED_PROVIDER=gemini` + `GEMINI_API_KEY` (+ `EMBEDDING_MODEL` 은 비우거나 `gemini-embedding-2`) → 서버 재시작 → 어드민 "임베딩 전체 다시 만들기" (또는 같은 설정으로 s09)
- 바꾼 결과 확인: `GET /api/health` 의 `providers.llm` · `providers.embed` · `models`

## 12. 남은 일 · 측정 필요

- [ ] 키 발급 후 `pnpm --filter web eval:live` 로 30문항을 **제공자별로** (`LLM_PROVIDERS=gemini` / `=openai`) 돌려 품질 비교 → 순서·smart 모델 확정. 1회 약 $0.05 (Gemini) / $0.01 (GPT).
