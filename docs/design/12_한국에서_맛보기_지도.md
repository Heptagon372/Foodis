# 12 한국에서 맛보기 — 주변 음식점 지도

> 탐험한 세계 음식을 **한국에서 바로 먹어볼 수 있는 곳**으로 이어 준다.
> 화면 `/taste/[slug]`(음식 상세 › 연결 탭 "📍 한국에서 맛보기"), 어드민 `/admin/places`.
> 확인일: 2026-10-02. 아래 URL 은 모두 이 날짜에 확인한 공식 문서다.

## 1. 원칙

1. **공식 API·공개 데이터만 쓴다.** 카카오·네이버 장소 페이지나 후기를 긁지 않는다(약관 위반).
2. **지어내지 않는다.** 평점·쿠폰·이벤트는 출처가 있는 것만 보여 주고, 화면에 출처와 확인 날짜를 붙인다.
3. **사용자 위치는 저장하지 않는다.** "내 주변"을 누를 때만 브라우저 Geolocation 을 묻는다. 좌표는 우리 서버를 거쳐 카카오 검색 한 번에만 쓰고 버린다. DB 와 로그에는 남기지 않는다. 캐시 키는 소수 셋째 자리(약 100m)로 반올림한 값만 쓴다.
4. **API 키는 서버에만 둔다.** 브라우저에 나가는 키는 지도 JS 키뿐이다. 이 키는 도메인 등록으로 보호한다.

## 4. 검색어 전략과 "판다"의 근거

`lib/places/kakao.ts buildQueries()` 는 다음 순서로 검색한다. 한 요청에 최대 3번 호출하고, 10곳 이상 모이면 멈춘다.

1. 한국어 음식 이름 (`쌀국수`) → `match=dish`
2. 영어 이름이 라틴 문자면 (`Pho`) → `match=dish`
3. 그 나라 요리 이름 (`베트남음식`. 표에 없는 나라는 `{나라} 음식`) → `match=cuisine`. 화면에는 "베트남 음식점 · 쌀국수 메뉴는 확인 필요"로 표시한다.
4. 어드민이 메뉴를 확인해 이어 둔 음식점(`restaurant_foods.confirmed`) → `match=confirmed`. 화면에는 "✔ 메뉴 확인됨"으로 표시한다. 검색에 안 잡혀도 사장님이 준 위치가 있으면 보여 준다.

음료(`course_type=drink`)는 카페(`CE7`)에서 찾고 3단계를 건너뛴다. 같은 거리라면 confirmed → dish → cuisine 순으로 놓는다.

## 5. 정렬 공식

- **가까운 순:** 카카오가 준 거리(m)로 정렬한다. 거리가 같으면 근거가 센 곳을 먼저 놓는다.
- **맛있는 순 (베이즈 평균):** 별 5개를 1–2개만 받은 곳이 1등을 하지 않게 한다.

  `score = (C·m + n_g·R_g + w·n_a·R_a) / (C + n_g + w·n_a)`
  m = 3.5 (사전 평균), C = 10 (사전 가중), w = 1 (앱 평점 가중), R_g/n_g = Google 평점/개수, R_a/n_a = 푸디 평균/개수

  - 평점이 없는 곳은 m 으로 꾸미지 않고 **맨 뒤**로 보낸다.
  - 후보 전체에 평점이 하나도 없으면 거리순으로 바꾸고 "평점 정보가 아직 없어요"라고 알린다.
  - 한 곳의 평가가 5건 미만이면 "평가가 아직 적어요"를 붙인다. 전체 평가가 10건 미만이면 "순위가 바뀔 수 있어요"라고 안내한다.
- **필터:** 포장·공동구매·쿠폰·이벤트 필터는 **확인된, 지금 유효한** 혜택만 센다. 포장은 Google `takeout` 도 함께 본다. "프랜차이즈 제외"는 `is_franchise=false` 로 확인된 곳만 남긴다(모르는 곳은 빼고, 동기화 전이면 그렇다고 안내).

## 6. 프랜차이즈 매칭 (`lib/places/franchise.ts`)

- **정규화:** NFKC 로 전각을 반각으로 바꾸고, 영문을 소문자로 바꾸고, 괄호 내용·공백·기호를 지운다.
- **지점명 제거:** 마지막 토큰이 `…점`이면 뗀다("강남역점", "2호점", "본점"). 단 "분식점·순대국점·반점"처럼 가게 종류를 뜻하는 말은 그대로 둔다. 토큰이 하나뿐이면 건드리지 않는다.
- **매칭 순서:** ① 지점명을 뗀 이름이 브랜드와 정확히 같으면 가맹이다. ② "미스터피자역삼점"처럼 붙여 쓴 경우는 브랜드(3자 이상)가 접두어이고 나머지가 지점명일 때만 가맹으로 본다. ③ 카카오 분류가 4칸 이상이면 마지막 칸(체인 브랜드명)과 맞춰 본다.
- **브랜드 목록:** 공정위 가맹정보 브랜드 목록에서 `indutyLclasNm=외식` 인 것만 받는다. 1글자 브랜드는 색인에서 뺀다.

## 9. 데이터 모델 (`supabase/migrations/0005_restaurants.sql`)

- `restaurants`: `kakao_place_id`(unique)·`place_url` / 사장님·어드민이 받은 이름·주소·전화·위치(`info_source`) / `google_place_id`·`google_checked_at` / `franchise_brand`·`is_franchise`
- `restaurant_foods(restaurant_id, food_id, source search|admin|report, confirmed)`
- `restaurant_offers(kind coupon|event|group_buy|takeout|info, title, detail, starts_at, ends_at, source owner|admin|report, verified, verified_by/at, created_by)`
- `restaurant_ratings(restaurant_id, user_id, food_id, stars 1–5, unique(restaurant_id,user_id))`
- `restaurant_rating_stats` 뷰: 평균·개수만 노출한다.
- `franchise_brands(normalized pk, brand_name, company, industry, source_updated_at, synced_at)`. 대표자 이름은 받지 않는다.
- **RLS**
  - 공개 읽기: restaurants, restaurant_foods, 그리고 **verified** 인 offers.
  - 제보 insert: 로그인 사용자만, `source=report`·`verified=false`·`created_by=auth.uid()` 일 때.
  - 평점: 본인 행만 select·insert·update.
  - 나머지 쓰기: 서버 라우트가 service_role 로 처리한다.

## 11. 사장님·파트너 온보딩 아이디어 (Phase 2 B2B)

07 문서 §8 수익 모델의 "식당·경험 연결"을 Phase 2 에 미리 시험해 본다.

1. **무료 등록:** 사장님이 카카오 장소 링크와 연락처를 남기면 푸디팀이 전화로 확인한다. 그 뒤 "메뉴 확인됨"과 쿠폰·이벤트·공동구매·포장 정보를 등록해 준다(`source=owner`).
2. **신뢰 장치:**
   - 모든 혜택에 "사장님 등록 · 날짜 확인"을 붙인다.
   - 쿠폰·이벤트는 마감일이 필수다.
   - 이용자 제보로 틀린 정보를 바로잡는다.
3. **제휴 라벨:** 나중에 유료 노출을 하더라도 정렬 알고리즘에는 영향을 주지 않는다. 대신 별도 섹션에 "제휴" 라벨을 붙인다(07 §8 원칙).
4. **지표:** 음식 상세 → 맛보기 진입률, 카카오맵/길찾기 클릭률, 등록 음식점당 평점 수.

## 12. 아직 못 한 것

- 실제 키로는 호출해 보지 않았다. 아래는 모두 가짜 응답 테스트로만 확인했다.
  - 카카오·Google·공정위 API: 응답 필드 이름(특히 공정위 `corpNm`, 응답 래퍼 모양)은 첫 동기화 때 확인해야 한다.
  - 카카오·네이버 지도: SDK 렌더링을 키가 생긴 뒤 브라우저에서 확인해야 한다.
- 네이버 지도는 마커 표시까지만 구현했다. 클러스터·오버레이는 없다.
- 네이버 검색 API 는 쓰지 않는다. `display` 가 최대 5개이고 페이지를 넘길 수 없어 근처 검색에 맞지 않는다. 저장 약관도 확인하지 못했다.
- 속도 제한·Google 하루 상한은 서버 인스턴스별 메모리 값이다. 여러 인스턴스로 운영하면 Upstash 같은 공유 저장소로 바꿔야 한다.
- 영업시간(`currentOpeningHours`)은 받지 않는다.
