# 🧭 취향 엔진 v1 (Taste Engine)

> 사용자가 **무엇을 누르고, 어디에 오래 머물고, 어떤 기능을 쓰는지**로 취향을 계산해 추천 순서를 정한다.
> 원칙은 세 가지다.
> 1. **처음에는 나라마다 가장 유명한 대표 음식을 반드시 먼저 소개한다.**
> 2. 신호가 쌓일수록 취향 점수의 비중을 키운다.
> 3. 추천 이유를 화면에 보여 준다.

## 1. 흐름

```
화면 행동 ──signal()/noteFeature()──▶ lib/client/taste.ts (localStorage "foodis:taste:v1", 이 기기에만)
                                         │
                                         ▼
                        lib/taste/engine.ts  buildProfile() → TasteProfile
                                         │              (맛 태그 · 나라 · 대륙 0~1, 기능 사용, 확신도)
                                         ▼
                        rankFoods(후보, 프로필) → [{food, score, reason}]
                                         │
            홈 "나라별 대표 음식 / 나를 위한 추천" (components/HomeView.tsx)
            Passport "내 취향 분석" (components/TasteCard.tsx)
```

| 구성 | 파일 |
|---|---|
| 계산 (순수 함수) | `lib/taste/engine.ts` · 테스트 `lib/taste/engine.test.ts` |
| 신호 저장 | `lib/client/taste.ts` |
| 카드 클릭 기록 | `components/TrackLink.tsx` (FoodCard 의 링크) |
| 유명도 순위 | `FoodSummary.fame_rank`. 미리보기 데이터는 `tools/gen-preview-catalog.mjs` 가 만든다 |

## 2. 신호와 무게

| 신호 | 어디서 | 무게 |
|---|---|---|
| `like` 좋아요 | 상세 · 카드 액션 (`passport.toggle`) | 4 |
| `tried` 먹어봤어요 | 〃 | 3 |
| `saved` 저장 | 〃 | 2.5 |
| `share` 공유 | (예약) | 2 |
| `ask` 이 음식으로 푸디에게 질문 | 상세의 🎙 · "비슷한 음식 물어보기" | 2 |
| `listen` 이야기 듣기 | 상세 "푸디가 이야기로 들려주기" | 1.5 |
| `view` 상세 열기 | `FoodDetailView` 마운트 | 1 |
| `click` 카드 탭 | 모든 FoodCard (`src` = home_rec · home_today …) | 1 |
| `dwell` 머문 시간 | 상세를 떠날 때. **10초 미만은 0**, 30초당 1, 최대 2 | 0~2 |
| `tab` 상세 탭 | 문화 · 식이 · 연결 탭 | 0.5 |
| `country` 나라 선택 | 세계 지도에서 나라 탭 | 0.5 (나라 · 대륙에만) |
| `skip` 지나침 | 같은 추천을 4번 보고도 누르지 않음 | −0.3 |

**기능 사용 횟수** (`noteFeature`)는 취향 점수에 넣지 않는다. 대신 "내 취향 분석" 카드에 보여 준다. 대상은 음성 질문(`voice`) · 글 질문(`text`) · 라디오(`radio`) · 지도(`map`) · 이야기 듣기(`listen`) · 공유(`share`) · 상세 탭(`tab:문화` 등)이다.

## 3. 프로필

- **시간 감쇠**: 반감기 21일. 무게에 `0.5^(경과일/21)` 을 곱한다. 취향은 바뀌기 때문이다.
- 맛 태그 · 나라 · 대륙별로 무게를 더한 뒤, 가장 큰 값으로 나눠 **0~1** 로 만든다.
- 온보딩에서 고른 맛은 태그 시작값 1로 넣는다. 확신도에는 넣지 않는다.
- **확신도** `c = 1 − e^(−양의 신호 합 / 12)`. 좋아요 3개면 약 0.63, 상세 5개를 30초씩 보면 약 0.7이다.

## 4. 추천 점수

```
score = c·(0.45·맛 일치 + 0.2·나라 친숙도 + 0.1·대륙 친숙도)
      + 유명도·(1 − 0.6·c)
      + 0.15·새로움(안 가본 대륙 1 / 안 본 나라 0.5)
      − 지나친 횟수 패널티(최대 0.4)
```

- **유명도** = `1 / (1 + (순위−1)/3)` → 1위 1.0, 2위 0.75, 4위 0.5이다. 순위가 없으면 0.15다.
- 초반(c≈0)에는 유명도가 점수를 거의 정한다. 신호가 쌓일수록 유명도 비중은 40%까지 줄고 취향 비중이 커진다.
- 이미 상세를 본 음식은 다시 추천하지 않는다.

### 반드시 지키는 규칙

1. **대표 음식 먼저.** 사용자가 그 나라 음식을 아직 2개 이상 보지 않았다면, 그 나라에서는 **유명도 상위 3개**만 추천한다. 신호가 아무리 많아도 처음 만나는 나라는 대표 음식으로 시작한다. (`signatureGate`)
2. **다양성.** 한 목록에 같은 나라는 초반(c<0.5)에 1개, 이후 2개까지만 넣는다. 안 가본 대륙 1자리는 항상 남긴다.
3. **오늘의 탐험.** 모두에게 같은 음식을 보여 준다. 각 나라 **1위 대표 음식**(사진이 있는 것) 중에서 날짜로 고른다.

### 추천 이유 (카드의 ✦ 문구)

점수에 가장 크게 기여한 항목 하나를 보여 준다.
- "대한민국 대표 음식" / "○○에서 사랑받는 음식"
- "좋아하는 매운맛"
- "자주 본 태국 음식"
- "아직 안 가본 대륙"

## 5. 개인정보

- 신호는 **브라우저 localStorage 에만** 저장한다. 서버로 보내지 않는다. 베타 KPI 이벤트(07 문서)와는 별개다.
- Passport "내 취향 분석" 카드의 **기록 지우기**로 언제든 처음 상태로 돌릴 수 있다.
- 최근 600개 신호만 보관한다.

## 6. 유명도 순위를 만드는 법

`tools/gen-preview-catalog.mjs` 가 나라 안에서 순위를 매긴다.
1. 사람이 고른 목표(`dish_targets.csv` 의 수동 행, 시드 순서 = 대표성)가 먼저 온다.
2. 그다음은 자동 후보다. 위키백과 **언어판 수**가 많은 순서다. 많은 언어로 소개된 음식일수록 그 나라를 대표한다고 본다.
