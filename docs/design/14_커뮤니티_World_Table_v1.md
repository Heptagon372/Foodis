# 14. 커뮤니티 World Table v1 (F-SOC-01)

> 02 문서에서 "사용자 없는 커뮤니티는 빈 화면 · 모데레이션 부담"으로 MVP 제외했던 기능을 플랫폼 확장으로 구현. 두 우려를 각각 **샘플 시드(미리보기)** 와 **규칙+LLM 사전 필터 + 신고 3건 자동 숨김**으로 다룬다.

## 1. 카테고리

| 갈래 | 키 | 화면 |
|---|---|---|
| 밥친구 | `buddy` | 같이 먹을 사람 찾기. 만날 시각 · 인원(나 빼고 1~20) · 참여 버튼 · 모집 상태(모집 중 / 완료 / 약속 지남) |
| 모임 | `diet` 다이어트 · `halal` 할랄 · `vegetarian` 채식 · `meat` 육식 · `collab` 콜라보 · `korean` 한식 · `chinese` 중식 · `western` 양식 · `japanese` 일식 · `etc` 기타 음식점 | 주제별 이야기방 |

카테고리 표는 `lib/community/categories.ts` 한 곳 — DB check 제약(0006) · API zod · 화면 칩이 같은 목록을 쓴다.

## 2. 기능

- **글쓰기** `/community/write`: 카테고리 · 제목(2~60) · 내용(~2000) · 위치(글자, ~60) · 사진 4장(브라우저에서 1280px JPEG로 축소) · 투표(질문 선택, 선택지 2~5개). 쓰는 동안 **푸디 추천** 칩이 제목·내용 단어로 카테고리를 제안한다(규칙 기반, 즉시·무료).
- **피드** `/community`: 전체 · 밥친구 · 모임(→ 10개 칩). 정렬 **AI 맞춤 · 최신 · 인기**. 주소 `?c=` 로 카테고리를 기억.
- **상세** `/community/:id`: 사진 넘기기, 투표(다시 고르면 변경), 따봉, 밥친구 참여, 공유(모바일 공유 시트 / 링크 복사), 신고, 내 글 삭제, 댓글(내 댓글 삭제). 서버 렌더 + OG 메타 → 공유 링크 미리보기.
- **음식 연결**: 글을 저장할 때 본문에서 DB 음식·나라 이름을 찾아 `food_slugs` 로 붙인다(`lib/community/tags.ts`). LLM이 아니라 이름 일치라 지어낸 음식이 붙지 않는다 → 카드의 `#음식` 칩이 음식 상세로 이어진다.

## 3. DB → AI 반영 흐름

```
카테고리 탭 · 글 열람 · 공유 ──/api/community/signals──┐
따봉 · 댓글 · 투표 · 참여 · 글쓰기 ── 각 라우트가 직접 ──┼─▶ community_signals (종류·카테고리·글 id만, 자유 텍스트 없음)
                                                        │
                    lib/community/trends.ts computeTrends ◀┘  감쇠 합(반감기 3일, 창 14일) → 카테고리별 열기 0~1 · 급상승
                                │
           ┌────────────────────┼─────────────────────────┐
           ▼                    ▼                         ▼
  AI 맞춤 피드 순서     푸디 브리핑 (briefing.ts)     모임 칩의 급상승 점
  rankForYou            LLM fast → 한 줄 요약 + 이어 물을 질문
  "왜 이 글?" 이유       실패·예산 초과·키 없음 → 템플릿
                         "푸디에게: …" 버튼 → 푸디 대화(DB 음식 추천)로
```

- **내 관심**은 브라우저에만 쌓는다(`lib/client/community.ts`, 반감기 14일). 피드 요청 때 0~1로 정규화한 숫자만 `?i=halal:1,korean:0.42` 로 보낸다. 어떤 모임을 자주 보는지는 식이·종교를 짐작할 수 있는 정보라 서버에 개인별로 남기지 않는다(07 문서 §3 개인정보 원칙). 설정 → 화면 → "커뮤니티 맞춤 기록"에서 보고 지울 수 있다.
- 맞춤 점수 = 내 관심 0.45 + 모두의 열기 0.2 + 반응(따봉·댓글·참여) 0.2 + 신선도 0.35, 지난 밥약속 −0.6. 가장 크게 기여한 항목을 카드의 이유 칩으로 보여 준다("자주 보는 할랄", "요즘 뜨는 채식", "반응 많은 글", "방금 올라온 글").
- 브리핑은 숫자를 LLM에 맡기지 않는다: 막대·급상승·음식 칩은 계산값, LLM은 문장만. 출력에 링크·전화번호가 있거나 상위 트렌드 밖 카테고리를 고르면 버리고 템플릿. 같은 트렌드 모양이면 30분 재사용. 비용은 `api_usage` 에 `community_briefing` 으로 남고 푸디와 같은 하루 예산을 쓴다.
- 신호는 추적 거부(DNT·GPC)·데모 모드면 보내지 않는다(07 KPI 이벤트와 같은 규칙). 보관 90일 권장: `select purge_old_community_signals();`

## 4. 안전 · 운영

| 장치 | 내용 |
|---|---|
| 로그인 | 운영(live)에서 쓰기·따봉·투표·참여·신고는 로그인 필요(401 → 로그인 안내, 돌아오기 `next`). 읽기는 게스트 가능 |
| 사전 필터 | `moderation.ts` ① 규칙: 전화번호 · 오픈채팅/메신저 아이디 · 링크 3개 이상 차단(밥친구 만남 안전) ② LLM(있을 때만, fail-open): 혐오·괴롭힘·성적·불법·광고만. 음식 비판·식이 이야기는 허용 |
| 사후 조치 | 신고 1인 1회, 3건 누적 → `status='hidden'` 자동(트리거). 어드민 재공개는 후속 작업 |
| 속도 제한 | 글 분당 3 · 하루 20 / 댓글 분당 6 · 하루 100 / 반응 분당 40 / 신호 분당 30 |
| 사진 | Storage 공개 버킷 `community` (1장 2MB, JPEG·PNG·WebP). 글 삭제 시 함께 삭제 |
| 위치 | 사용자가 적은 약속 장소 글자만 저장(기기 좌표 X). 상세에서 카카오맵 검색 링크 |

## 5. 모드

- **live**: Supabase 키 + `0006_community.sql` 적용 → `supabase-store.ts`.
- **preview**: 키가 없거나 마이그레이션 전 → 메모리 저장소 + 샘플 글 12개·댓글·2주치 신호(`seed.ts`). 화면에 미리보기 배너, 작성자 이름에 "· 샘플". 게스트도 브라우저 익명 id로 써 볼 수 있다(데모용). 서버를 다시 켜면 처음으로.
