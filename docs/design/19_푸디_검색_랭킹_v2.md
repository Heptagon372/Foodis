# 🔎 푸디 검색·랭킹 v2 — 1만 개 데이터를 AI 가 알아듣게

> 2026-10-07. 플랫폼 QA·화면 최적화는 [20 문서](20_플랫폼_QA_1만개_최적화.md). 음식 1만 개 정리본(PR #24, 공개 10,163개)을 푸디 대화 파이프라인(02 문서 · 04 문서 RAG ①~⑧)에 연결한 설계·구현 기록.
> 02 문서의 의도·슬롯 규칙을 **맛·조리법·코스·재료·상황·알레르기 슬롯**으로 넓히고, 04 문서의 `match_foods` 점수식(0.55·유사도 + 0.30·취향 + 0.3)을 **신호별 정규화 가중합 + 계단식 조건 + MMR 다양화**로 바꿨다.
> 원칙은 그대로다: **사실은 DB 에서만, AI 는 해설만.** 새로 늘어난 것은 "질문을 DB 가 아는 말로 옮기는 층"과 "1만 개 중 무엇을 먼저 보여줄지 정하는 식"이다.

## 2. 데이터 층 — 사실을 먼저 바로잡는다

**알레르기 표준 키** (`lib/diet/allergens.ts`). 사용자가 고르는 9종 + 데이터에만 있는 7종(표시·경고용).

| 키 | DB 에 나오는 표기 | 키 | DB 에 나오는 표기 |
|---|---|---|---|
| dairy | dairy · 우유 · 유제품 · 유당 | mollusc | 조개류 · 오징어 · 홍합 · 굴 … |
| wheat | wheat · 밀 · 밀가루 | mustard | 겨자 |
| egg | egg · 계란 · 달걀 · 난류 | celery | 셀러리 |
| fish | fish · 어류 · 생선 | buckwheat | 메밀 |
| nuts | nuts · 견과 · 견과류 · 호두 · 잣 … | sulfite | 아황산류 |
| peanut | peanut · 땅콩 | barley · rye | 보리 · 호밀 |
| shellfish | shellfish · 갑각류 · 새우 · 게 | soy · sesame | 대두 · 참깨 |

- 읽는 순간 `canonAllergens` 로 키를 통일한다 (색인 · 카드 · 상세 화면 · 식단 경고 모두).
- SQL(`match_foods`)에는 `avoidTerms` 로 **두 표기를 다** 넘긴다 → DB 를 정리하기 전·후 모두 안전.
- DB 자체 정리는 `supabase/migrations/0011_allergen_keys.sql` (선택, 여러 번 실행해도 안전).

**식이 자기모순 검사** (`lib/diet/consistency.ts`). 재료 이름을 낱말로 나눠 동물성(우유·버터·치즈·꿀 …)·고기(햄·생선·라드·육수 …)를 찾는다.
식물성 대체품(땅콩버터 · 코코넛 밀크 · 콩고기 · 채소 육수)과 '콜라드'의 '라드' 같은 겹침은 뺀다.
`비건 yes` + 동물성 재료 → `depends`, `채식 yes` + 고기 → `depends`. **낮추기만 하고 올리지 않는다** (03 문서 정직한 불확실성).
→ 푸디는 "조리법에 따라 달라요, 확인해 주세요"라고 말하고, 원본 데이터는 어드민에서 고친다.

**세계 유명도** (`apps/web/lib/content/popularity.json`). Wikidata 언어판 수 L (중앙값 5 · 상위 1% 53 · 피자 149). `tools/gen-fame-rank.mjs` 가 fame.json 과 함께 만든다.

## 3. 푸디가 알아듣는 말 (`lib/foodi/vocab.ts` · `query.ts`)

질문을 **구조화 질의(QuerySpec)**로 옮긴다. DB 의 통제 어휘가 곧 AI 의 어휘다.

```
"안 매운 감자 요리, 돼지고기는 빼고"
→ { notTags: [spicy], ingredients: [감자], notIngredients: [돼지고기(차슈·베이컨·햄·라드 … 포함)] }
"비 오는 날 튀긴 간식"
→ { methods: [[deep_fried, fried]], courses: [[snack]], soft: { tags: [hot, soup, rich], label: "따뜻한 국물" } }
"땅콩 알레르기 있는데 태국 음식"
→ { allergens: [peanut] } + 나라 TH   (땅콩을 '원하는 재료'로 읽지 않는다)
```

| 슬롯 | 어휘 | 한국어 표현 예 | 쓰임 |
|---|---|---|---|
| 맛·특징 | 29 (sour … fruit) | 매콤·얼큰 → spicy, 국물·탕·스프 → soup, 바삭·아삭 → crunchy | 원하는 것: 점수 / 빼는 것: 하드 필터 |
| 조리법 | 15 | 튀긴 → {deep_fried, fried}, 구운 → {grilled, roasted, baked} (묶음) | 같은 계열은 0.5 |
| 코스 | 12 | 디저트·후식, 간식·야식, 음료·차·커피, 반찬, 아침 | 가까운 코스 부분 점수 (soup↔stew 0.6) |
| 재료 | 개념 11 + 데이터 사전 2,404 낱말 | 닭·치킨 → 닭이 든 재료 전부, 돼지 → 돼지·차슈·베이컨·햄·라드…, 감자·병아리콩·코코넛 … | 주재료 1 · 부재료 .7 · 양념 .4 |
| 상황 | 9 | 비 오는 날 · 더운 날 · 해장 · 술안주 · 다이어트 · 야식 … | **약한 신호**(점수 0.5 무게, 거르지 않음) |
| 범주어 | 39 | 만두 · 피자 · 커리 · 빵 … ("만두 추천해줘") | 이름에 그 말이 든 음식 |
| 알레르기 | §2 표 | "땅콩 알레르기 있는데" · "새우 알러지가 있어요" | 이번 답에서 프로필처럼 하드 필터 |

해석 규칙:
- **부정**: 앞 "안·덜" / 뒤 "말고·빼고·없는·싫·못 먹·알레르기" → 빼는 쪽. "맵지 않은"·"순한" 같은 활용형은 따로 표.
- **겹침 순서**: 음식·나라 이름 구간 → 재료 개념(단어 전체 차지 — "돼지고기 빼고"가 '고기 전부 빼기'가 되지 않게) → 맛 → 조리법·코스 → 범주어 → 데이터 재료 사전.
- 한 글자 재료(쌀·꿀·무 …)는 뒤가 조사·"요리"일 때만 ("무슨"의 무, "파스타"의 파 방지).
- **음식 이름의 쓰임**: "김치 **들어간** 요리" → 김치가 든 음식(김치 자체 ✕), "만두 **추천해줘**" → 만두 종류, "만두 **같은** 음식" → 비슷한 음식.
- '지도에 없음' 판정 전에 확인: 그 말이 재료·맛·코스로 읽히면 장소가 아니다 ("감자 요리" · "국물 요리").
- LLM 이 의도를 분류할 때(규칙이 못 정할 때만)도 같은 어휘로 받는다 — `IntentOutput` 의 `tastes · methods · courses`는 enum, `ingredients`는 데이터 재료 사전으로 다시 읽어 **사전에 없으면 버린다**.

## 4. 이름 인식 (`lib/foodi/names.ts`)

1. **띄어쓰기 무시 최장 일치**: 똠 얌 꿍 = 똠얌꿍. 겹치면 긴 이름이 이긴다.
2. **짧은 이름의 경계**:
   - 한 글자(회·전·묵·쌈·난): '그 음식을 묻는' 꼴일 때만 — "회 추천해줘" ○, "난 뭐 먹지?" ✕
   - 두 글자: 문장이 음식 이야기이고, 앞이 글자가 아니고, 뒤가 끝·조사·음식 관련 말일 때만 — "부자 알려줘" ○, "부자 되는 음식" ✕, "부자가 되고 싶어" ✕
   - 세 글자·띄어 쓴 이름: 뒤가 다른 낱말로 이어지면 더 긴 이름의 일부 — "로스트 치킨"의 로스트 ✕
3. **나라·대륙 이름 안의 이름은 버린다** ("아시아"의 아시). 나라 이름을 품은 음식 이름은 살린다 (튀르키예 커피).
4. **같은 이름**(47쌍): 발화의 나라 → 대표성 순 ("소바" → 일본, "브라질 소바" → 브라질).
5. **오타 교정**: 정확히 없으면 자모 편집거리. 음절을 초·중·종성으로 풀어 Levenshtein 거리 d 를 재고, 3음절 이하 d ≤ 1 · 5음절 이하 d ≤ 2 · 그 이상 d ≤ 3 이면 같은 음식으로 본다. 후보는 음절을 절반 이상 공유하는 이름만 (역색인). "똠양꿍" → "똠 얌 꿍".
6. 괄호 설명이 붙은 이름은 괄호 밖 이름으로도 찾는다 ("하이밀히(건초 우유)" → 하이밀히).

검증기(`generate.ts validate`)도 같은 인식기로 "후보 밖 음식명"을 찾는다 — "아시아의 바다를 담은 스시"를 '아시' 언급으로 오인하지 않는다.

## 5. 검색 흐름 (`lib/foodi/retrieve.ts`)

```
질문 ─ 규칙 의도·슬롯(QuerySpec) ─┬─ ① 하드 필터: 식이(yes·depends) · 알레르기(프로필 ∪ 질문) · 나라 · 대륙
       ∥ 질의 임베딩               │                · 빼는 맛/재료/조리법/코스 · 이번 대화에서 본 음식
                                   ├─ ② 의미 후보: pgvector 상위 120 (임베딩 없으면 신호만 끈다)
                                   ├─ ③ 점수: 통과한 음식 전부(최대 1만)에 §6 식
                                   ├─ ④ 계단식 조건 충족 → 식이 확실성 → MMR 로 5개 (§7)
                                   └─ ⑤ 5개만 본문(소개·이야기·재료) 조회 → LLM 은 그 안에서 고르고 설명 (matched = 고른 이유)
```

### 5.1 색인
- 1만 개 × 가벼운 필드(이름 · 나라 · 태그 · 조리법 · 코스 · 식이 · 알레르기 · 재료 · 유명도 · 사진/이야기/역사 유무)를 서버 메모리에 둔다.
- Supabase 에서 1,000행씩 6개 동시 → **약 3.5초**(처음 한 번), 색인 만들기 0.17초, 이후 0ms. 10분마다 뒤에서 새로 받는다(옛 색인으로 답하면서).
- 서버 시작 때 미리 받는다 (`instrumentation.ts`) → 첫 음성 질문이 기다리지 않는다.
- 재료 통계: 재료별 음식 수 df, 역문서빈도 `idf(i) = ln((N+1)/(df(i)+1))`, 재료 → 음식 역색인.

### 5.2 LLM 에 넘기는 후보
기존 필드 + `region · cooking_method(한국어) · course(한국어) · main_ingredients(≤4) · matched`.
`matched` 는 점수에서 나온 사실("주재료 감자", "튀긴 요리", "아직 안 가본 나라", "태국 대표 음식", "식이 조건 확실") — 프롬프트 7번 규칙이 이걸 이유로 쓰게 한다. 템플릿 답의 카드 이유도 같은 값.

### 5.3 임베딩 문서 v2 (`lib/admin/embed-batch.ts`)
질의와 **같은 한국어 이름표**로 쓴다 (맛·조리법·종류는 vocab.ts 표).

```
마무앙꾸안 (Mamuang kuan) — 태국 음식
망고를 말려 과일 가죽 형태로 만든 태국 전통 단 간식이에요. …
맛·특징: 달콤한, 새콤한, 쫄깃한, 과일
주재료: 망고
부재료: 설탕, 코코넛 밀크
종류: 디저트
식이: 채식, 할랄, 글루텐 프리, 유제품 없음      ← 재료와 모순인 yes 는 빼고 쓴다 (§2)
(문화 이야기 앞 300자)
```

- 모델: `EMBED_PROVIDER=gemini` → gemini-embedding-2, 1536차원, 문서 "title: {이름} | text: {본문}", 질의 "task: search result | query: {질문}".
- 만들기: `apps/web` 에서 `pnpm embed:foods` (없는 것만, 끊겨도 이어서) · `--stale` (내용이 바뀐 것까지) · `--dry-run`. 1만 개 약 **$0.7**.
- **Gemini 무료 등급 한도**: 임베딩 분당 100건 · **하루 1,000건** (2026-10-07 실측). 일괄 생성은 분당 80(사용자 질문 몫 20을 남김), 429 는 기다렸다 재시도, 하루 한도면 안내하고 끝낸다(다음 날 이어서). 결제를 켜면 `EMBED_RPM=3000`.
- **95% 규칙**: 공개 음식의 95% 이상에 임베딩이 있을 때만 의미 신호를 켠다. 일부만 있으면 그 음식들만 의미 점수를 받아 순위가 쏠린다.
- **의미 검색 RPC**: `0012_match_foods_v2.sql` — 거리순 + LIMIT 이라 HNSW 인덱스를 탄다(v1 은 계산 점수로 정렬해 전체 스캔). 앱은 v2 가 있으면 쓰고 없으면 v1.
- 어드민 버튼도 같은 문서·같은 모델, 한 번에 1,500개씩 (300초 제한), 남은 수를 보여준다. "전체 다시"는 `text_used` 와 지금 문서를 비교해 **바뀐 것만** 다시 만든다.

역할 분담: **구조 조건(재료·맛·코스·알레르기)은 규칙과 식이, 뉘앙스("해장", "명절 음식", "할머니 손맛")는 임베딩이** 맡는다. 해장 관련 음식 13개는 이름이 아니라 소개글에 '해장'이 있어서 의미 신호가 있어야 잘 찾는다.

## 6. 점수식 (`lib/foodi/rank.ts`)

모든 신호를 0~1 로 맞추고, **이번 질문에서 켜진 신호의 가중치만 다시 합 1 로 정규화**해 더한다.

$$S(f) = \frac{\sum_{k \in K_{on}} w_k \, s_k(f)}{\sum_{k \in K_{on}} w_k} + \varepsilon \cdot u(f)$$

| 신호 | 식 | 켜지는 때 |
|---|---|---|
| s_sem 의미 | 벡터 후보 120개 안 min-max: `(cos − cos_min) / (cos_max − cos_min)`, 후보 밖 0 | 질의 임베딩 성공 + 음식 임베딩 있음 |
| s_slot 조건 충족 | 명시 조건 무게 1, 상황 조건 0.5 의 가중 평균 (아래) | 조건이 하나라도 있을 때 |
| s_taste 취향 | Food DNA 코사인 `Σ_{t∈T_f} w(t) / (‖w‖₂ · √|T_f|)` — 태그가 많다고 유리하지 않다 | 취향 가중치가 있을 때 |
| s_fame 대표성 | `0.35 · 1/(1+ln r) + 0.65 · g(L)`, `g(L) = clamp((ln(1+L) − ln 3)/(ln 81 − ln 3))` | 항상 |
| s_novel 새로움 | 안 가본 나라 1 · 가본 나라의 새 음식 0.4 · 이미 본 음식 0 | 탐험 기록이 있을 때 |
| s_qual 풍부함 | 사진 0.5 + 문화 이야기 0.3 + 역사 0.2 | 항상 |
| s_diet 식이 확실성 | 요청 식이마다 yes 1 · depends 0.4 의 평균 | 식이 조건이 있을 때 |

조건 충족도의 항목별 값: 맛 태그 있음 1 (국물·면·밥·빵은 코스로도 인정) · 조리법 같음 1 / 같은 계열 0.5 · 코스 같음 1 / 가까움 0.3~0.6 · 재료 주 1 / 부 0.7 / 양념 0.4 (개념 태그만 맞으면 0.8) · 범주어가 이름에 1 / 재료에 0.6.

대표성 예: 김치(나라 1위, L=77) 0.99 · 바하마 거북이 수프(1위, L=21) 0.75 · 일본 10위(L=40) 0.62. → 음식 5개뿐인 나라의 1위가 김치와 같은 점수를 받지 않는다 (v1 의 나라 안 순위만 쓰면 둘 다 1.0).

가중치 (질문 모양별):

| 모양 | sem | slot | taste | fame | novel | qual | diet |
|---|---|---|---|---|---|---|---|
| 열린 추천 ("오늘 뭐 먹지?") | .30 | – | .15 | .25 | .15 | .15 | .10 |
| 조건 추천 ("튀긴 간식", "비 오는 날") | .25 | .35 | .10 | .10 | .08 | .07 | .05 |
| 식이 찾기 ("비건 디저트") | .20 | .20 | .10 | .15 | .10 | .10 | .15 |
| 문화 이야기 | .25 | .15 | .05 | .20 | .10 | .25 | .05 |

예) 임베딩·취향·탐험 기록이 없는 "감자 요리" → 켜진 신호 slot .35 · fame .10 · qual .07 → 정규화하면 slot 0.67 · fame 0.19 · qual 0.13. **조건 맞는 음식이 유명한 음식을 이긴다.**

흔들림 ε·u(f): `u = hash(씨앗, 음식 id) ∈ [0,1)`, 씨앗 = 날짜 + 사용자. 같은 날·같은 사람은 같은 순서(답 캐시 24시간과 맞물림). ε = 0.03(조건 있는 질문, 동점 깨기) · **0.2(열린 추천 — 대표 음식 상위권이 날마다 돌아가며 1순위)**.

## 7. 계단식 조건 + 다양화

1. **조건 충족 계단**: 명시 조건을 모두(≥0.99) 만족하는 후보가 3개 이상이면 그 안에서만, 아니면 절반 이상(≥0.5), 아니면 하나라도 맞는 것. 상황 조건은 계단에 넣지 않는다(점수에만) — "비 오는 날"이 후보를 거르지 않게.
2. **식이 확실성 계단**: 식이 조건을 말했고 전부 yes 인 후보가 3개 이상이면 그 안에서 — "비건 디저트"에 '조리법에 따라 다름'을 앞세우지 않는다.
3. **MMR**: `argmax_f [λ·S(f) − (1−λ)·max_{g∈선택} 겹침(f,g)]`, 겹침 = 0.6·[같은 나라] + 0.4·태그 자카드, λ = 0.75 (비슷한 음식은 0.85). → 후보 5개가 실측에서 늘 5개 나라.

## 8. 비슷한 음식 (compare_similar)

후보 = 검수된 관계(양방향, 13,464개) ∪ 임베딩 이웃 40 ∪ **흔하지 않은 재료(idf > 2)를 공유하는 음식** 200 (역색인, 1만 개를 다 훑지 않는다).

$$sim(a,b) = \frac{0.35\cos + 0.25\,WJ_{ing} + 0.15\,J_{tag} + 0.08\,m + 0.07\,c + 0.10\,rel + 0.05\,away}{\sum w\ (\text{켜진 것})}$$

- 재료 가중 자카드 `WJ = Σ min(w_a(i), w_b(i)) / Σ max(w_a(i), w_b(i))`, `w_x(i) = 역할(주 1 · 부 .7 · 양념 .4) × idf(i)` — 설탕·소금을 공유한 것보다 병아리콩을 공유한 쪽이 훨씬 비슷하다.
- m: 조리법 같음 1 / 같은 계열 0.5, c: 코스 같음 1 / 가까움, rel: 지역 변형 1 · 비슷한 맛 .9 · 같은 재료 .7 · 같은 조리법 .6 · 역사 .5, away: 다른 나라 1 (FOODIS 는 "Different Cultures, One Table").
- 임베딩이 없으면 cos 항을 빼고 정규화. 0.3 미만(관계 없는 것)은 '비슷하다'고 말하지 않는다.
- "다른 나라에도" → 같은 나라는 뺀다. 비슷한 음식이 모두 식이·알레르기에 걸리면 엉뚱한 음식 대신 "조건에 맞지 않아요" (02 문서 규칙 그대로).
- 이유: "같은 재료 병아리콩·타히니", "같은 조리법(튀긴)", "비슷한 맛(고소한·크리미한)", "지역 변형".
