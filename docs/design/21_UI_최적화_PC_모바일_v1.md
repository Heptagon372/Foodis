# 📐 UI 최적화 v1 — PC · 폰 · 태블릿 어디서든 불편하지 않게 (2026-10-07)

> 요청: "PC든 폰이든 불편하지 않도록". 화면을 폭별(320 · 360 · 375 · 768 · 820 · 1280 · 1440px)로 자동 점검(가로 넘침 · 40px 미만 터치 목표 · 11.5px 미만 글자)하고, 눈으로도 확인해서 실제로 걸리는 것만 고쳤다.
> 계정 연동(카카오 · Google · Instagram)은 [06 문서 §7](06_회원_로그인_동기화_v1.md) 참고.

## 1. 점검 결과 요약

| 폭 | 결과 |
|---|---|
| 폰 320 ~ 375px | 가로 넘침 0. 대부분 이미 잘 맞아 있음 → 작은 터치 목표·겹침만 손봄 |
| 태블릿 · 반쪽 창 PC (768 ~ 1023px) | 폰 폭(448px) 열이 가운데 덩그러니 → **본문 폭을 넓힘** |
| PC (1024px ~) | 가로로 넘기는 카드 줄을 마우스로 못 넘김, 세계 지도가 화면보다 길어 휠이 지도 확대에 걸림, 라디오 채널이 잘림 |
| 공통 | Windows 첫 화면에 국기가 "KR" 글자로 비침, 5분마다 첫 방문자가 ~10초 기다림, DB 순간 오류 한 번에 1분간 미리보기 샘플이 보임 |

## 2. 바꾼 것

### 레이아웃
- **태블릿·반쪽 창(md, 768px~)**: `AppFrame` 본문 `max-w-md` → `md:max-w-2xl`. 하단 탭 바·시트는 그대로(한 손 폭).
- **가로 카드 줄 화살표** `components/ScrollRow.tsx`: 마우스·트랙패드(`pointer: fine`)에서만 줄 양끝에 좌우 화살표(40px). 끝에 닿은 쪽·넘칠 게 없는 줄은 저절로 숨는다(ResizeObserver 로 늦게 채워지는 내용도 다시 잼). 터치는 지금처럼 밀어서. 랜딩 캐러셀과 같은 훅(`useCarousel`)을 쓴다.
  - 적용: 음식 상세 '연결' 줄(`RelationRow`) · 맛집탐방 분류/음식/찾은 음식점 줄 · 푸디 시트·사진 질문의 추천 카드 · 커뮤니티 게시판 칩 · 모임 줄/주제 칩 · 뉴스 키워드 칩 · 홈 추천 줄
- **라디오 채널**: 폰은 밀어서 넘기는 줄, md 이상은 3칸 격자 (6개 채널이 넓은 화면에서 잘려 보이던 것)
- **세계 지도(PC)**: 높이를 화면에 맞춤 `lg:max-h-[max(26rem, 100dvh − 내비 − 15rem)]` + 폭은 꽉 채움(남는 폭은 바다). 지도 전체와 확대 버튼이 한 화면에 들어오고, 페이지를 내리려다 휠이 지도 확대에 걸리지 않는다. 나라 패널·확대 이동은 그대로 동작 확인.

### 터치 목표 · 겹침
- 지도 확대/축소/전체 버튼 36 → 40px, 홈 타일의 재생·화살표 버튼 36 → 40px, 맛집탐방 분류 칩 36 → 40px
- 맛집탐방 반경 슬라이더: 보이는 막대는 4px 그대로, 잡는 높이는 24px (`padding-block` + `background-clip: content-box`)
- 홈 히어로: 좁은 폰(320px)에서 오른쪽 위 사진 출처 칩이 'LET'S EXPLORE' 와 겹침 → 위 여백 `pt-14`

### 속도 · 깜빡임
- **국기 글꼴을 그리기 전에** (`lib/client/flags.ts`, `layout.tsx` `<head>`): 예전 `FlagPolyfill` 은 하이드레이션 뒤(useEffect)에 글꼴을 붙여 Windows 첫 화면에 "KR"·"BR" 글자가 비쳤다. 이제 `<head>` 인라인 스크립트가 지원 여부를 판별하고(같은 캔버스 방식) 글꼴을 `preload` + `font-display: block` 으로 연결한다. 국기를 지원하는 기기(macOS·iOS·Android)는 아무것도 받지 않는다. `country-flag-emoji-polyfill` 의존성은 뺐다(글꼴 파일은 자체 호스팅 그대로).
- **목록 캐시 stale-while-revalidate** (`lib/content/cache.ts`): 5분이 지나면 지난 값을 바로 주고 뒤에서 한 번만 새로 받는다. 예전엔 5분마다 첫 요청이 음식 1만 개를 다시 받느라 ~10초 멈췄다(dev 측정: 홈 9.9초 → 캐시 갱신 중에도 즉시). 다시 받다 실패하면 지난 값을 계속 쓰고, 어드민 `invalidateContent()` 는 여전히 즉시 비운다.
- **live/미리보기 판정** (`lib/content/index.ts`): 한 번 live 였는데 확인 요청만 잠깐 실패하면 live 유지 + 10초 뒤 재확인. 처음부터 실패(서버 막 켜진 직후)한 경우도 1분이 아니라 5초만 기억 — 실제 사용자에게 미리보기 샘플이 1분씩 보이던 문제.

## 4. 홈 랜덤 음식 슬라이드 (추가 요청)

> "처음 홈피에 음식들 슬라이드로 랜덤해서 넣어서 옆으로 넘어가게끔"

- 위치: 폰 = 히어로 바로 아래(첫 화면에서 보이게) · PC = 히어로와 출처 띠 사이
- 고르기 `lib/content/slides.ts` `pickSlides`: 홈 요청마다 서버가 음식 1만 개 전체에서 **사진 있는 음식을 나라가 겹치지 않게 18개** 무작위로. 화면에 필요한 칸만 넘겨 HTML 이 가볍다 (테스트 3개)
- 화면 `components/FoodMarquee.tsx`: 진짜 가로 스크롤 줄을 requestAnimationFrame 으로 천천히 민다(폰 26px/s · PC 34px/s). 같은 목록을 두 번 이어 붙여 끝없이 돈다 — 첫 줄 끝에서 같은 모양인 처음으로 옮겨 이음새가 안 보인다
  - 손가락으로 밀 수 있고(만지면 3초 멈춤), PC 는 ◀ ▶ 로 두 칸씩, 마우스를 올리거나 키보드 포커스가 들어오면 멈춤
  - ⏸ 버튼(자동으로 움직이는 콘텐츠는 멈출 수 있어야 한다), '동작 줄이기' 설정이면 처음부터 멈춤, 화면 밖이면 돌리지 않음
  - 사진은 CSS 배경 — 숨은 쪽 트리(폰/PC)에서는 내려받지 않는다. 두 번째 줄은 스크린리더·탭 순서에서 뺌
- 확인: 폰 375px 히어로 아래 노출·가로 넘침 0(격자 안에서 줄이 부모 폭을 늘리던 것 `min-w-0` 으로 막음) · 끝(2,806px)에서 이음새 없이 처음으로 · 터치 후 3초 뒤 다시 흐름 · PC ▶ 두 칸(416px) 이동
