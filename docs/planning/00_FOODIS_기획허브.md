# 🌍 FOODIS — 세계 음식 문화 AI 플랫폼 기획 허브

> 🌍 **FOODIS (FOOD) — Different Cultures, One Table.**
>
> "검색하지 않아도 된다. 푸디에게 물어보면 된다."
>
> 자체 음식·문화 DB + 사용자 데이터를 AI 음성 인터페이스로 연결해, 스마트폰 하나로 세계 음식 문화를 **탐험**하는 플랫폼. 성공회대 제17회 IT 경진대회 출품용.

## 한 줄 정의

> **FOODIS는 자체 구축한 세계 음식·문화 지식 DB를 AI가 사실의 기준으로 삼아, 사용자가 음성으로 "푸디야, 오늘은 어디로 떠나볼까?"라고 묻는 것만으로 자신의 취향·식이 조건에 맞는 새로운 나라의 음식과 문화를 발견하고, 그 기록을 '나만의 식탁'으로 쌓아가는 음식 문화 탐험 플랫폼이다.**

## 기획자 관점 핵심 판단 5가지

1. **정체성은 '탐험 서비스'다. 검색·추천·레시피 앱이 아니다.** 모든 화면과 AI 답변은 "다음 탐험으로 이어지는 링크"를 반드시 하나 이상 가진다.
2. **MVP는 하나의 완결된 경험에 집중한다.** "음성으로 질문 → DB 기반 추천 → 음식 상세(문화·식이·연결) → Passport에 기록" 이 한 루프가 끊김 없이 돌면 경진대회에서 이긴다. 지도·이미지 인식·커뮤니티는 과감히 뒤로 미룬다.
3. **AI는 생성기가 아니라 '해설자·연결자·개인화 엔진'이다.** 사실(국가·재료·할랄·알레르기)은 DB에서만 나오고, AI는 그것을 설명·연결·개인화한다. 이 원칙이 할루시네이션 방지의 전부다.
4. **데이터가 곧 기술 난이도다.** 30개국 × 5~7개 음식(약 150~200건)을 출처 포함 구조화 데이터로 직접 구축하고, 음식 간 관계(같은 재료/조리법/역사적 이동)까지 넣는다. 심사위원이 "그냥 ChatGPT 아니냐"고 물을 때의 답이 여기 있다.
5. **Voice First + 카드 UI.** 음성만으로 끝내지 않는다. 답변마다 음식 카드가 함께 뜨고, 카드에서 탐험이 이어진다. 발표 데모의 임팩트도 여기서 나온다.

## AI 이름 제안

> 🎙️ **푸디 (Foodi)** — 호출어 "푸디야". 서비스명(FOODIS)과 일관되고, 2음절로 음성 호출에 적합. 영문 표기 Foodi. 대안: 테이블(Tably), 포크(Forky).

## 기획 진행 방식 (기획 단계)

기획은 아래 6단계로 진행한다. 각 단계의 산출물·기간·상태는 `08_기획단계_로드맵`(.md / .csv)에서 관리한다. Notion 원본: https://app.notion.com/p/3ec6afff66e78178a4f6fd0e0df15e76
데이터 구축 키트는 `foodis-data/` 폴더 (README 참고).

| 단계 | 목표 | 핵심 질문 | 완료 조건 |
|---|---|---|---|
| P0 방향 확정 | 한 줄 정의·핵심 경험·MVP 경계 합의 | 우리는 무엇을 안 만드는가? | 팀 전원이 한 줄 정의를 같은 문장으로 말할 수 있다 |
| P1 사용자·시나리오 | 페르소나 3개, 이용 시나리오, 음성 대화 스크립트 | 사용자는 왜 내일도 켜는가? | 데모에서 실제로 말할 질문 10개 확정 |
| P2 데이터 설계·구축 | DB 스키마 확정, 130개국(심화 30) 280 음식 데이터 입력(출처 포함) | AI가 참조할 '사실'은 어디서 오는가? | 데이터 QA 통과, 관계 데이터 300건 이상 |
| P3 AI·음성 설계 | RAG 파이프라인, 프롬프트, 답변 스키마, STT/TTS 선정 | DB에 없는 걸 물으면 어떻게 답하는가? | 할루시네이션 테스트 셋 30문항 통과 |
| P4 UX/UI 설계 | 스크린 맵, 와이어프레임, 디자인 시스템, 첫 화면 연출 프로토타입 | 모바일에서 한 손으로 탐험이 되는가? | Figma 프로토타입으로 핵심 루프 클릭 가능 |
| P5 개발·발표 준비 | MVP 구현, 데모 시나리오, 발표 자료, Q&A 준비 | 심사위원 앞에서 음성이 한 번에 되는가? | 데모 리허설 3회, 오프라인 fallback 준비 |

## 원칙 (모든 문서에 적용)

- **기능보다 하나의 강력한 경험.** 기능 추가 제안은 "핵심 루프를 강화하는가?"로 판정한다.
- **DB가 사실, AI는 해설.** 사실 정보 생성 금지. 출처·불확실성 표기.
- **Voice First, Card Always.** 음성 답변에는 항상 시각 카드가 동반된다.
- **기술은 문제 해결 수단.** 각 기술 선택에 "어떤 사용자 문제를 푸는가" 한 줄을 붙인다.
- **모든 끝은 다음 탐험의 시작.** 막다른 화면(dead-end)을 만들지 않는다.
